# A3 프로필 200명 생성기

`gen_profiles.ts`는 첫 런인 붕괴 후 여섯 번째 겨울의 인구를 만든다. 소개 문장은 만들지 않으며 `line`은 모두 빈 문자열이다. 외부 서비스와 모델을 호출하지 않는다.

## 실행과 확인

저장소 루트에서 Node.js 22.18 이상으로 실행한다. 기본 시드는 `s1-winter-six`다.

```sh
node s1/tools/gen_profiles.ts
node s1/tools/gen_profiles.ts --check
node --test s1/tools/gen_profiles.check.ts
```

다른 시드와 임시 출력 폴더를 지정할 수 있다. 출력은 `s1/` 안으로 제한한다. 기본 출력 위치는 현재 작업 폴더에 영향을 받지 않는다. 지정한 폴더 경로는 현재 작업 폴더를 기준으로 해석한다.

```sh
node s1/tools/gen_profiles.ts --seed winter-six-2 --output-dir s1/.local/another-seed
node s1/tools/gen_profiles.ts --seed winter-six-2 --output-dir s1/.local/another-seed --check
```

`s1/`에서는 설치된 `tsx`로도 실행할 수 있다. `npm test` 한 번이 Vitest 테스트와 이 생성기의 검사(`npm run test:profiles`)를 모두 돌린다.

```sh
npm exec --offline -- tsx tools/gen_profiles.ts --check
npm test
npm run validate -- data
```

`--check`는 파일을 바꾸지 않고 두 출력의 바이트가 일치하는지 확인한다. 생성 JSON은 `s1/.gitattributes`로 LF 줄바꿈을 유지한다. 시드뿐 아니라 생성기 버전과 레퍼런스 파일도 같아야 같은 결과가 나온다. 레퍼런스가 추가되거나 수정되면 다시 생성해야 한다.

## 출력과 분포

| 파일 | 내용 |
|---|---|
| `s1/data/profiles.json` | 콘텐츠 가이드 1.1의 필드 12개로 된 프로필 배열 200개 |
| `s1/generated/profile_families.json` | 가족 관계, 시드, 입력 SHA-256, 임시 목록 사용 안내 |

프로필에 가이드에 없는 필드를 추가하지 않았다. 가족 정보는 A1이 검사하는 `data/` 밖에 두었다. 가족 파일의 `parents`와 `children`은 프로필 id를 참조한다. 같은 `children` 목록의 두 사람은 형제다. 같은 가족은 같은 공동체와 성의 어근을 공유한다. B1 성별 형태가 있으면 각 이름의 성별에 맞는 성 표기를 쓴다.

| 공동체 | 인원 | 0~15세 | 65세 이상 | 0~5세 열차 출생 | 기본 경위와 다른 인원 |
|---|---:|---:|---:|---:|---:|
| 꼬리칸 | 90 | 18 | 4 | 4 | 18 |
| 앞칸 | 30 | 5 | 3 | 1 | 6 |
| 기술·의무진 | 30 | 3 | 3 | 1 | 6 |
| 경비대 | 25 | 2 | 2 | 1 | 5 |
| 기관실 | 25 | 2 | 8 | 1 | 5 |
| 합계 | 200 | 30 | 20 | 8 | 40 |

아이 비율은 15%, 노인 비율은 10%다. 열차 출생은 공동체별 다른 경위 20%에 포함한다. 공동체별 기본 경위는 꼬리칸 `refugee`, 앞칸 `bought`, 기술·의무진 `rescue`, 경비대 `force`, 기관실 `depot`다. 경비대·기관실의 아이에게 옛 경찰·군 경력이나 차고 근무 경력을 주지 않는다. 앞칸 아이의 `bought`는 가족이 낸 물건·권력으로 함께 탄 경위다.

모든 아이 30명에게 같은 공동체의 부모 두 명을 연결한다. 가족은 16묶음이며 14묶음에는 형제가 있다. 가족에 속하는 사람은 62명이다. 부모와 자녀의 나이 차이는 18~50세이고 한 사람이 여러 가족에 중복되지 않는다. 배우자 관계와 가족 밖의 친구·원수는 이번 작업에 포함하지 않는다.

기관실은 노인 8명과 나이가 많은 성인으로 구성한다. 다른 공동체보다 평균 나이가 높다. 고향은 폴란드·독일·체코가 중심이고, 피난 경위에는 우크라이나·슬로바키아·헝가리·리투아니아를 섞는다. 국적은 공동체를 결정하지 않는다. 가족의 고향은 맞추되 열차 출생자의 고향은 `열차, 출생 정차역 미상`으로 남긴다. 열차 출생자의 출신 꼬리표는 부모에게서 받는다.

고향 후보는 폴란드 서부·독일 동부·체코의 도시와 소도시 각 20곳, 피난민 나라마다 4~5곳이다. 큰 도시만이 아니라 볼슈틴 주변 소도시(라코니에비체, 카르고바, 바비모스트 등)와 경로 위의 역 도시를 섞었다. 한글 표기는 `ref/names/transliterate.py`의 결과를 붙여 쓰고, 굳어진 표기가 있는 곳(슈트랄준트, 켐니츠, 마그데부르크)은 그 표기를 따른다.

### 이름 규칙

- 200명 안에서 원어 전체 이름도, 한글 전체 이름도 겹치지 않는다. 철자는 달라도 한글이 같은 경우(Lukas와 Lucas)도 겹친 것으로 본다. 풀이 모자라면 다른 이름을 재사용하지 않고 오류로 멈춘다.
- 가족은 성을 공유하고 이름은 서로 다르다.
- 피난민(`other`)은 이름, 성, 고향이 한 언어로 묶인다. 우크라이나 이름에는 우크라이나 성과 우크라이나 고향이 붙는다. 원어 표기는 B1이 준 문자 그대로(우크라이나어는 키릴 문자) 둔다.
- 헝가리 이름은 원어와 한글 모두 성을 앞에 쓴다(예: 토트 페렌츠).
- 리투아니아 성에 기혼형이 있으면 가족의 어머니에게 기혼형을 쓴다. 가족 밖의 여성은 B1의 기본 여성형을 쓴다.

## B1·B6 입력

기본 입력 위치는 저장소의 `ref/`다. `--ref-dir`로 다른 레퍼런스 폴더를 읽을 수 있다. 입력은 읽기만 한다. 파일이 없을 때는 작은 임시 목록을 쓰고, 존재하는 파일의 형식이 잘못됐을 때는 오류로 끝낸다.

B1은 `names/pl.json`, `de.json`, `cz.json`, `other.json`을 읽는다. 다음 형식을 받는다.

```json
{
  "given_names": [
    { "original": "Marta", "korean": "마르타", "gender": "female" }
  ],
  "surnames": [
    { "original": "Welenik", "korean": "벨레니크" }
  ]
}
```

`given_names` 대신 `first_names`도 받을 수 있다. 이름 목록은 배열 또는 `{ "male": [...], "female": [...] }` 객체이며, 최상위 `male`, `female` 목록도 받는다. 성은 공통 표기 또는 `{ "male": { "original": "...", "korean": "..." }, "female": { "original": "...", "korean": "..." } }` 형태이고, `female_married`가 있으면 기혼형으로 쓴다. 항목의 `language`(`uk`, `sk`, `hu`, `lt` 등)가 있으면 같은 언어끼리만 짝짓는다. 가족 이름에는 제외 후 서로 다른 이름이 최대 4개 필요하다.

`names/famous_blocklist.json`은 전체 이름 문자열의 배열, `{ "original": "전체 원어 이름", "korean": "전체 한글 이름" }` 배열 또는 그 배열을 가진 `names` 객체를 받는다. 원어와 한글 전체 이름을 모두 대조하며 대소문자, 연속 공백, 결합 악센트를 정규화한다. 제외 목록과 중복 금지 때문에 쓸 이름이 모자라면 오류를 낸다. `ref/names/`가 없을 때 쓰는 임시 목록의 성은 가상으로 조합했다.

B6은 실제 B6 작업본의 `entries` 형식을 받는다.

```json
{
  "entries": [
    {
      "text": "법랑 머그잔",
      "preference_options": ["like", "dislike"],
      "tags": {
        "age_groups": ["child", "young", "adult", "middle", "elder"],
        "communities": ["tail", "engine", "guard", "medtech", "front"],
        "home_countries": ["폴란드", "독일", "체코"],
        "seasons": ["한파", "해빙기"]
      }
    }
  ]
}
```

작은 입력에는 `{ "likes": [...], "dislikes": [...] }`도 사용할 수 있다. 각 항목은 한국어 문자열 또는 `text`와 위 태그를 가진 객체다. 태그는 항목 바로 아래에 둘 수도 있다. `countries`에는 `pl`, `de`, `cz`, `other`, `seasons`에는 `winter`, `thaw`도 사용할 수 있다.

나이 태그는 0~15세, 16~29세, 30~49세, 50~64세, 65~85세로 구분한다. 첫 런은 겨울이므로 한파 항목을 고른다. 열차 출생자는 나라 태그를 부모의 고향으로 대조한다. 좋아하는 것과 싫어하는 것은 서로 다르게 고른다. 태그가 맞는 항목이 없으면 임시 선호로 대체하며 대체 횟수를 가족 파일의 `preference_fallbacks`에 기록한다. 구할 수 없는 옛 물건도 선호가 될 수 있으므로 `availability`는 선호 필터로 사용하지 않는다.

## 확인 결과와 남은 문제

2026-10-05 확인 결과(A1·A2·B1·B6가 들어간 main 기준):

- 커밋된 데이터는 B1 이름 풀·유명인 제외 목록과 B6 선호 풀로 만들었다. 임시 목록 경고 0건, 선호 대체 0건이다.
- `npm test`: Vitest 476개와 생성기 검사 10개가 통과한다. 생성기 검사는 임시 목록으로 101개 시드, 저장소의 B1·B6로 30개 시드에서 분포, 가족, 이름 중복 0, 피난민 이름의 언어 일치, 리투아니아 어머니의 기혼형을 확인한다.
- `--check` 재현, `npm run validate -- data`(200항목, 오류 0개·경고 0개), `npm run build`가 통과한다.
- 기본 시드의 고향은 65곳이다.

남은 문제:

- 피난민 이름 가운데 우크라이나어·슬로바키아어·리투아니아어 표기는 B1에서 '미확인' 초안이다. 표기를 고치면 다시 생성해야 한다.
- 리투아니아 성 일부는 위키낱말사전(CC BY-SA)에서 왔다. 출시 데이터에 그대로 넣을지는 따로 정한다.
- 문장 채우기(`line`)는 A5에서 한다.
