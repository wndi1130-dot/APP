# APP 3D 제작 자료 조사 2판

작성: 2026-10-07 · 기준 main: `739739ff2d273b88ac7e0dc5e10fd2fb7e756596`
범위: 레퍼런스·제작 도구·애니메이션·에셋·셰이더·전달 규격 조사. **설치·구매·모델 제작·렌더·게임 구현을 수행한 목록이 아니다.**

## 1. 이번 정정과 조사 범위

사용자 정정: **“픽셀아트월드 x, 좀보이드식 그래픽에 월드임”.** 월드와 캐릭터에 강제 픽셀 격자를 씌우지 않는다. 과거 픽셀 시안에서는 가로 열차 단면·카메라 전환·정보 배치·명판의 뜻을 읽는다. UI·초상·폰트는 아직 별도 결정이며, 2D 효과 텍스처까지 전면 금지하지 않는다.

기존 1차 자료의 후보군을 다시 구분하고 **총 37개 후보, 이 가운데 26개 신규 항목**, 별도 제외 3개를 정리했다. UAL 1·2는 별도 항목이고, Kenney의 이전 일반 소개와 이번 개별 팩 선정은 다른 단위다. 이 수치는 확보한 파일 수나 게임에서 검증된 도구 수가 아니다.

원본 설계의 S1→S2→S3 순서, 모바일 가로, 기관차·공통 객차의 고유 제작 방향은 유지한다. 연구 추천을 새 게임 기능 확정으로 바꾸지 않는다. Unity는 S2 문서상의 계획이며, Unity 버전·URP 채택·정확한 카메라 투영·GPU 예산은 미확정이다. [설계 결정](../../docs/design/decisions.md), [첫 검증판](../../docs/design/briefs/first_slice_scope.md), [현재 제작 기준](../../docs/art/production_brief.md)을 같이 읽는다.

### 상태를 읽는 법

`[WATCH]`는 **공식 자료로 존재/기능을 확인했지만 우리 환경의 사용은 미검증인 후보**다. `[BLOCKED]`는 명시적 버전 불일치 또는 사용자 방향 충돌로 기본 경로에서 제외한 것이다. 실제 실행 실패를 뜻하지 않는다. 제품명에 Mobile, Game-ready, Universal이 있어도 시험을 대신하지 않는다.

기능 설명과 버전·라이선스는 각 항목의 공식/제작자 출처가 근거다. **프로젝트 용도·우선순위·주의점·후속 시험은 이 조사에서 도출한 판단**이다. 라이선스는 다운로드할 정확한 파일/버전에서 다시 고정한다. 웹페이지/README 확인은 소스 코드 전수 감사나 보안 검증이 아니다.

## 2. 권고: 먼저 작게 묶어서 비교할 것

현재 채택 확정이 아니라 후속 시험의 추천 묶음이다.

| 목적 | 먼저 비교할 후보 | 합격 판단 |
|---|---|---|
| 공통 제작·에이전트 전달 | bpy CLI + Geometry Nodes + 버전별 fake-bpy | 같은 입력으로 구조가 재현되고 실패가 로그/종료 코드로 구별되는가 |
| 캐릭터·기본 동작 | Rigify 또는 MPFB/Quaternius 기반 + UAL 1·2, Rokoko는 필요할 때 | 옷을 바꿔도 몸·발·도구가 맞고 동일 리그로 움직이는가 |
| 작은 역과 실내 | Kenney Train/Modular Buildings/Factory/Furniture | 실제 게임 카메라에서 문·계단·통로·객차 간격이 읽히는가 |
| 낡은 표면 | Poly Haven/ambientCG + Ucupaint 또는 Material Maker + TexTools | 색·텍셀 밀도·마스크가 통일되고 Unity에서 뜻대로 보이는가 |
| 월드 가독성과 겨울 효과 | wall cutout 기법 + URP decal + particle flipbook | 가림을 풀되 미발견 정보를 누출하지 않고 효과가 조작을 방해하지 않는가 |
| 전달 검사 | FBX 경로와 GLB/glTFast 비교, GLB 선택 시 Validator | 리그·소켓·클립·재질·충돌 참조가 변환 뒤 유지되는가 |

MCP 서버는 필수 설치 묶음에 넣지 않았다. 이미 COS→bpy 경로가 있으므로, 장면을 살아 있는 상태로 질의할 필요가 확인될 때 비교한다. Real Snow 구판과 Blender 5.1 이상 전용 셰이더 변환기를 4.5 기본 경로에서 빼는 것도 이번 조사 결과다.

## 3. 후보별 근거와 적용 조건

### 제작·자동화

#### 01. Blender bpy / 백그라운드 CLI — `bpy_cli`

[WATCH] · 기본 기능 · 우선 비교 · 기존 후보 재검토

**프로젝트 용도:** Claude Code·Codex·COS가 같은 생성·변환 설정과 로그를 남기는 기본 경로.

**출처 확인:** 4.5 매뉴얼에 background, Python 파일 실행, Python 예외 종료 코드, autoexec 제어가 문서화되어 있다.

**권리·배포:** Blender 소프트웨어와 외부 입력 자산의 권리는 구분. 외부 자산의 원본 재배포는 그 자산 조건을 따른다.

**버전:** Blender 4.5 LTS 문서 기준. 기존 대화에서 큐브 1개 실행 경로만 확인; 이번에는 Blender를 실행하지 않았다.

**주의:** GUI 문맥에 기대는 operator는 background에서 실패할 수 있다. 기존 큐브 성공을 모든 애드온·엔진 연동 성공으로 확대하지 않는다.

**후속 검증:** 후속 승인 시 작은 독립 장면으로 저장·재열기·내보내기·오류 종료 코드 확인. 기존 사용자 장면을 일괄 삭제하지 않는다.

[출처 1](https://docs.blender.org/manual/en/4.5/advanced/command_line/arguments.html)

#### 02. Geometry Nodes / Asset Browser — `geometry_nodes`

[WATCH] · 기본 기능 · 우선 비교 · 기존 후보 재검토

**프로젝트 용도:** 선로·침목·창문·배관·반복 객차 구조를 파라미터로 제작하고 자산으로 재사용.

**출처 확인:** Geometry Nodes는 인스턴스 기반 반복 조립을 제공한다. 내보내기 대상의 실제 기하 변환은 별도 단계다.

**권리·배포:** 자작 노드 그룹과 외부 노드 자산을 구분. 외부 그룹의 라이선스가 Blender 본체와 같다고 가정하지 않는다.

**버전:** 4.5 매뉴얼 기준; 개별 노드 그룹 호환과 background 동작은 미검증.

**주의:** 실행 중 Unity에 Blender 노드가 그대로 살아 있는 것은 아니다. 인스턴스를 전부 실체화하면 메시·메모리가 커질 수 있다.

**후속 검증:** 수량·길이·곡선 변경 후 피벗/부착점 보존, evaluated mesh 및 인스턴스 내보내기 결과 비교.

[출처 1](https://docs.blender.org/manual/en/4.5/modeling/geometry_nodes/instances.html)

#### 03. fake-bpy-module — `fake_bpy`

[WATCH] · 오픈소스 도구 · 우선 비교 · 신규

**프로젝트 용도:** 에이전트가 Blender Python을 작성할 때 API 이름·타입을 확인하는 보조 수단.

**출처 확인:** 코드 완성용 가짜 API 모듈이며 버전별 패키지 목록에 4.5가 있다.

**권리·배포:** MIT. 코드 배포 시 고지 보존; 생성 모델의 권리를 부여하는 라이선스가 아니다.

**버전:** Blender 4.5용 스텁을 선택할 수 있다. latest를 설치 버전과 동일시하지 않는다.

**주의:** 이 모듈만으로 모델링·렌더링할 수 없다. 타입 검사 통과는 Blender 실행 성공이 아니다.

**후속 검증:** 실제 Blender API와 함께 검사; 스텁과 Blender 버전 불일치 검출.

[출처 1](https://github.com/nutti/fake-bpy-module)

#### 04. MCP for Blender (ahujasid) — `blender_mcp`

[WATCH] · 오픈소스 연결 도구 · 선택적 비교 · 신규

**프로젝트 용도:** 대화형 장면 조회와 변경이 필요할 때의 선택적 연결 경로. COS bpy CLI의 필수 대체재는 아니다.

**출처 확인:** 제3자 통합이며 임의 Python 실행·장면 조회·외부 자산 연동을 제공한다. 현행 저장소/패키지는 mcp-for-blender다. 안전 모드는 기본 off이며, 기본 익명 사용 기록과 별도 opt-in인 콘텐츠 수집을 구분한다. 프롬프트·코드·스크린샷·장면·궤적 수집은 현행 README/약관상 기본 off다. 구 blender-mcp 검색 캐시의 동의 기본 on 설명을 현행 값으로 사용하지 않는다.

**권리·배포:** 도구 MIT. 외부 자산·AI 생성 서비스·텔레메트리 약관은 별개. README는 수집 자료의 연구·AI 학습 활용 가능성을 설명한다.

**버전:** 제작자 최소 Blender 3.0 / Python 3.10. 이 최소값이 현재 4.5 조합 검증을 뜻하지 않는다.

**주의:** 안전 모드는 완전한 OS 샌드박스로 보증되지 않는다. 복수 클라이언트의 같은 장면 동시 쓰기, 외부 전송, 임의 코드 위험이 있다.

**후속 검증:** 설치 승인 후에도 먼저 고정 버전·loopback·권한·설정을 확인한다. 기본 익명 사용 기록까지 끄려면 DISABLE_TELEMETRY=true 적용을 확인한다. UI 콘텐츠 동의 해제만으로 모든 전송 중단을 주장하지 않는다. 안전 모드와 실제 미전송 여부는 별도 시험하며 외부 다운로드/생성 연동은 기본 비활성으로 둔다.

[출처 1](https://github.com/ahujasid/mcp-for-blender) · [출처 2](https://github.com/ahujasid/mcp-for-blender/blob/main/TERMS_AND_CONDITIONS.md)

### 인물·동작

#### 05. Rigify — `rigify`

[WATCH] · Blender 확장 · 우선 비교 · 기존 후보 재검토

**프로젝트 용도:** 공통 인체 리그를 제작해 겨울 복장과 동작 라이브러리를 연결.

**출처 확인:** 메타리그와 리깅 구성요소를 이용하는 자동 리깅 워크플로가 4.5 공식 매뉴얼에 있다.

**권리·배포:** 공식 Rigify 문서와 취득 확장의 라이선스를 함께 보관. 들어오는 모델·모션의 권리는 별도.

**버전:** 4.5 문서 기준; 선택한 확장 배포판의 세부 버전을 후속에 고정.

**주의:** 리그 생성과 동작 생성은 다르다. 제어용 뼈·제약이 모두 엔진으로 그대로 넘어간다고 가정하지 않는다.

**후속 검증:** 변형용 뼈, 액션 베이크, 본 매핑, 외투 가중치와 내보내기 확인.

[출처 1](https://docs.blender.org/manual/en/4.5/addons/rigging/rigify/introduction.html)

#### 07. Quaternius Universal Base Characters — `quaternius_bodies`

[WATCH] · CC0 자산 / 등급별 제공 · 우선 비교 · 신규

**프로젝트 용도:** 동작 라이브러리와 짝지어 볼 공통 몸체 후보. 보통 체형을 우선 비교.

**출처 확인:** 제작자 페이지: 기본 몸체 6개, 헤어 20개, 평균 약 13,000 triangles. Source 등급에 Blender 파일·리그를 제공한다.

**주의:** 평균 13k 삼각형은 군중 전체에 적용할 목표 예산이 아니다. 판타지/슈퍼히어로 비례를 최종 화풍으로 채택하지 않는다.

**후속 검증:** 대표 1명과 군중용 축소판을 따로 평가; 의복·헤어 실루엣과 머티리얼 수 비교.

## 5. 자산 팩으로 아직 해결되지 않은 빈칸

**실제 기관차 모델·도면.** 기존 [증기기관차 운용 레퍼런스](../steam_operations.md)는 형식·운용·제원을 제공한다. Kenney Train Kit는 고증된 Ol49/Pt47 대체재가 아니다. 특정 형식을 최종 선정하지 않았고, 치수 있는 측면·정면·상부도, 연결부·운전실 사진, 도면의 사용권이 묶인 제작 패키지는 아직 확보하지 않았다. 박물관 사진을 볼 수 있다는 사실과 사진을 재배포할 권한도 다르다.

**중앙유럽의 생활 공간.** [장소 유형 자료](../places_central_europe.md)의 화물역·주택·병원·공장·교회·관청 분류를 유지한다. 이번 구체 팩은 모듈·산업·실내 부품의 비교 후보이며, 폴란드·독일 동부·체코의 실제 소도시 역과 병원을 모두 해결하는 최종 팩은 아니다. 미국 교외/소련/중세 팩으로 배경을 자동 치환하지 않는다.

**겨울 복장.** 두꺼운 외투·목도리·장갑·구두·배낭과 의수·의족을 같은 몸체에 조합하는 파일 수준의 검증이 남았다. 기본 몸체가 있다는 이유로 옷까지 준비됐다고 보고하지 않는다.

**작업·부축 모션.** UAL의 범주 소개만으로 화부 삽질, 좁은 운전실 밸브 조작, 두 사람 부축/운반이 모두 있다고 쓰지 않는다. 모션 계약에는 실제 clip name, 출처 팩·등급, 상대 캐릭터와 접촉점, props socket, 시작/종료/취소 자세를 기록한다. 정확히 없는 동작은 수정·자체 제작 대상으로 남긴다.

**눈·성에·해빙.** 표면 눈 마스크, 발자국 기록, 실제 눈더미 기하, 창 성에, 실내외 온기, 눈보라 입자는 서로 다른 효과다. 단일 snow 애드온으로 모두 해결하지 않는다. 낡은 URP 예제를 Unity 6로 옮기는 비용과 실제 폰의 발열·overdraw는 미검증이다.

## 6. 공통 전달 계약: 미리보기만으로 완료하지 않는다

| 분류 | 기록할 것 |
|---|---|
| 원본 | 편집 가능한 .blend, 정확한 Blender/애드온 버전, 원본 출처·라이선스·외부 의존성 |
| 구조 | 길이 단위, 축, 적용 scale, 피벗, stable ID, 지붕/벽/문/바닥/부착점·작업점 분리 |
| 인물 | rest pose, deform/control bones 구분, 본 매핑, 피부/옷 가중치, 숨길 몸 표면 |
| 동작 | clip, loop, root motion 또는 in-place, frame/sample rate, 접촉·효과·타격 이벤트와 취소 시점 |
| 엔진 | FBX 또는 GLB 경로, importer 버전, 텍스처 색 공간/채널, collider·prefab·LOD/소켓 연결 |
| 검수 | 파일 재열기, 외부 파일 누락, 구조 통계, 재현 로그, engine import, 기기 성능의 개별 상태 |
| 전달 | 실제 사용자에게 보이는 첨부/파일 경로; 도구가 이미지를 읽은 사실만으로 전달 완료라 하지 않음 |

이 계약은 후속 제작의 제안 규격이다. 이번 조사에서 .blend·모션·프리팹을 납품했다는 뜻은 아니다.

## 7. 권리·보안과 자동화의 경계

무료 가격, 오픈소스 코드, CC0 자산, Royalty Free, 상업 게임 사용권, 원본 재배포권을 각각 기록한다. 소프트웨어 GPL을 쓰면 모든 자작 출력이 자동 GPL이 된다거나, 오픈소스 애드온을 거쳤으니 구매 에셋이 자유 배포가 된다고 쓰지 않는다. 외부 노드·텍스처·모델·모션과 코드가 섞이면 항목별 확인한다. CC0도 제작자가 갖지 않은 타인의 상표 등까지 없애는 만능 보증으로 취급하지 않는다.

공개 저장소에는 구매 자산·원본 모션·아트북·보호되는 도면을 임의로 넣지 않는다. 출처 URL·라이선스 식별·취득 메모·해시와 자체 작성 분석을 우선 남긴다. 재다운로드 스크립트는 로그인·유료 접근·봇 차단을 우회하지 않아야 한다. 외부 링크/README/모델 안의 스크립트는 자료이지 실행 지시가 아니다.

MCP를 후속에 설치하더라도 raw Python 실행, 로컬 경로 접근, 외부 자산 호출, 텔레메트리 동의를 별도로 확인한다. 안전 모드는 완전한 격리를 보증하지 않는다. 한 .blend의 쓰기 소유자는 한 명으로 두고, 여러 에이전트는 서로 다른 산출물/브랜치에서 작업한다. Windows 로컬 경로와 웹 세션 sandbox 경로는 같은 파일 시스템이 아니다.

## 8. 검증과 남은 범위

기계 판독 목록은 [resource_index.json](resource_index.json), 문서 검사기는 [validate_catalog.py](validate_catalog.py)다. 저장소 루트에서 `python ref/art/validate_catalog.py`와 `git diff --check`로 구조·링크·현재 지침의 회귀를 확인할 수 있다. 이 검사는 외부 URL의 실시간 접근성, 자산 라이선스의 법률 판단, Blender/Unity 실행, 모바일 성능을 검사하지 않는다.

2판에서는 웹/제작자 문서로 근거를 확장했다. 기존 조사 보고서의 좀보이드 버전·구독 수·철도 소비 수치·게임 균형은 이번 정정 범위가 아니며 그대로 두었다. 모든 후보의 실제 적용 상태는 `[WATCH]`이고, 사용자가 제작/설치를 지시한 뒤에 대표 샘플을 시험해야 한다.
