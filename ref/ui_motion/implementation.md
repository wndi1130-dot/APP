# 구현 방식 비교 — 원작 설명과 자체 재현 후보

## 1. 비슷하게 보이는 네 효과를 구별

| 방식 | 움직임의 원리 | 맞는 용도(제안) | 한계 |
|---|---|---|---|
| 불규칙 마스크 reveal | 고정 질감/거리값의 임계치를 시간에 따라 바꿈 | 일반 버튼, 카드, 탭 | 흐르는 유체가 아님. 텍스처와 곡선이 투박하면 싼 dissolve처럼 보임 |
| 노이즈/flow 기반 가장자리 왜곡 | UV 또는 경계 위치를 이동 | 선택된 면의 약한 호흡, 정치 테두리 | 반복 노이즈가 읽히기 쉬움. 글자도 같이 왜곡하면 안 됨 |
| 리본·입자+렌더타깃 합성 | 입자 흔적을 텍스처에 그려 UI/후처리와 합성 | 의회 큰 전환, 한정된 중요 장면 | 여러 렌더 경로와 RT·정렬·입자 비용. G02에서 이 계열을 확인 |
| 실제 유체 시뮬레이션 | 속도/압력/염료장을 반복 계산 | 독립 데모·고사양 장식 비교 | 버튼 누를 때마다 필요한 기술이 아님. 원작 채택 근거 없음 |

앞의 두 방식은 이 프로젝트를 위한 재현 제안이다. 세 번째는 **G02의 Council 설명에 한정해** 원작 근거가 있다. 네 번째의 공개 예제는 [T12](sources.md#t12)이며 원작 자산이나 원작 코드가 아니다.

## 2. 버튼 번짐의 최소 구성안

레이어를 입력 영역, 텍스트/아이콘, 선택 배경, 번지는 경계, 선택적 먼지로 나눈다. 안정된 클릭 영역과 글자는 고정하고, 배경/경계만 움직인다. opacity가 0이 된 장식이 클릭을 계속 가로채지 않도록 별도 정책을 둔다.

제안하는 단순 reveal은 다음처럼 생각할 수 있다. 이것은 원작 코드를 역설계한 수식이 아니다.

`q(x) = 거리(누른 지점 또는 버튼 중심, x) + 큰 노이즈(x) + 작은 노이즈(x)`

`alpha(x,t) = 1 - smoothstep(p(t)-w, p(t)+w, q(x))`

q가 작은 곳부터 열린다. q 범위를 정규화하거나 시작/끝을 별도 고정해 처음에는 완전히 안 보이고 끝에는 필요한 부분이 완전히 나타나게 한다. w는 경계 폭, p는 reveal 진행이다. 두 번째 낮은 대비 층을 약간 늦게 진행시키면 가장자리에 묽은 잔상이 남는 듯한 안을 비교할 수 있다. 숫자·문자에는 이 alpha를 직접 적용하지 않는다.

물속의 잉크에 가까운 모양을 원하면 둥근 큰 덩어리, 가는 가지, 농도 차이와 잔상을 조합한다. 종이에 스미는 표현이면 섬유 방향과 마른 경계 쪽을 조정한다. 매번 완전 무작위로 모양이 바뀌는 대신 seed를 제한하고, 같은 버튼의 중단/역방향 전환에서 모양이 튀지 않게 한다.

빠르게 보이는 효과는 단순한 scale-up과 다르다. 실루엣의 일부가 먼저 열리고 다른 부분이 따라오게 하되, 의미·라벨은 바로 보여 주는 안을 비교한다. 최종값을 읽기 위해 애니메이션 종료를 기다리지 않게 한다.

## 3. S1 웹에서 비교할 경로

**A. 가장 단순한 안:** 사전 제작/사용권이 확인된 알파 마스크와 transform/opacity. 실제 확산은 아니어도 반복 비용과 입력 안정성을 먼저 볼 수 있다.

**B. SVG/CSS 안:** feTurbulence의 노이즈와 feDisplacementMap을 선택 배경/마스크에만 적용한다. mask-image는 alpha/luminance 모드와 로딩 실패를 따로 점검한다. 넓은 화면 전체 필터를 상시 갱신하지 않는다. [T01](sources.md#t01) [T02](sources.md#t02) [T03](sources.md#t03)

**C. 국소 WebGL 안:** 같은 reveal 값을 fragment shader에서 계산한다. 필요한 영역만 렌더하고 DOM의 의미 구조/포커스/버튼은 유지한다. 실제 fluid 예제 T12는 비용 비교의 상한선이지 필수 의존성이 아니다. 이번에는 코드·프로토타입을 만들지 않았다.

재생 조율은 Web Animations API 같은 선택지를 비교할 수 있다. cancel은 finished promise 거부를 포함하므로 오래된 완료 콜백과 에러 경로를 처리한다. 스크롤로 바뀐 터치는 pointercancel로 준비 반응만 취소하고 명령은 실행하지 않는 안을 둔다. [T04](sources.md#t04) [T16](sources.md#t16)

## 4. Unity 단계에서 비교할 경로

| 후보 | 담당 역할 | 도입 전 확인 |
|---|---|---|
| 공식 Shader Graph UGUI 샘플 | 버튼·계기·배경과 상태별 재질 | Canvas/UGUI용, 엔진/패키지 버전과 mask·한글 텍스트 |
| UIEffect v5 | dissolve/mask/melt와 알파 질감·효과 조율 | alpha 채널 규칙, 중단/역재생, material 공유, timeScale |

| ParticleEffectForUGUI | 제한된 먼지·리본·입자 | UI 정렬·mask·vertex·CPU/배칭 비용 |

근거: [T07](sources.md#t07) [T09](sources.md#t09) [T10](sources.md#t10) [T11](sources.md#t11). 이 도구들이 FP1/2/TWOM에 사용됐다는 뜻은 아니다. Blender 모션 클립이나 Shader Graph 자산이 S1의 DOM에서 자동 재생되는 것도 아니다.

UIEffect의 자동 shader time은 timeScale 영향을 받는다고 README에 적혀 있다. 전술 일시정지 중에도 메뉴가 살아 있어야 하는 상황은 unscaled 재생 경로를 별도로 확인한다. 소리·메뉴 전환 clock과 실제 연구 진행 clock을 합치지 않는다. [T09](sources.md#t09)

## 5. 상태와 시간의 소유권

입력 준비 → 유효성 확인 → 명령 승인/거절 → 화면 피드백 순서를 나눈다. 게임 결과는 애니메이션 종료 함수가 아니라 기존 게임 로직이 소유한다. 새 연출이 완료되어야만 법이 제정되거나 재고가 차감되는 구조로 바꾸지 않는다.

버튼별 isHovered/isPressed/isSelected만으로 모든 화면을 표현하지 않는다. 화면의 opening/open/closing, 승인 요청 pending, 실제 selected, unavailable 이유, unread/complete를 구분한다. pending 중인 작업에 같은 명령을 두 번 보내지 않고, 되돌릴 수 없는 결과에 시각적 역재생을 논리 undo처럼 붙이지 않는다.

오래된 전환은 마지막 사용자 의도와 현재 화면 상태에 따라 취소한다. 빠른 A→B→A 이동이 전환을 세 개 줄 세우지 않게 한다. 메뉴를 닫아도 비밀 투표 결과·연구 진행·일지 기록은 기존 데이터에서 복원한다. 취소된 pressed 효과는 성공 소리·성공 배지로 이어지지 않는다.

## 6. 모바일·가독성 검수 제안

셰이더를 텍스처 없이 만들었다는 말이 계산 비용 0을 뜻하지 않는다. Unity의 공식 성능 메모도 복잡한 절차 셰이더의 비용을 경고한다. 정적 배경/텍스트와 자주 변하는 장식을 분리하는 안은 Canvas 재구성과 배칭을 함께 측정한다. [T08](sources.md#t08) [T15](sources.md#t15)

후속 비교 항목: 필터/RT 면적, 노이즈 샘플 수, 투명 overdraw, 메모리, Canvas 재구성, raycast, 글자 mask, 첫 렌더 지연, 프레임 시간 p95/p99와 장시간 발열. 어떤 휴대폰에서 몇 ms라는 예산은 아직 정하지 않았다. 화면의 큰 부분을 뒤틀거나 계속 일렁이게 하는 안은 동작 감소 모드에서 제거한다. [T05](sources.md#t05)

하늘색은 지지에만 쓴다는 최신 프로젝트 의미를 유지한다. 연구 선택 색을 시원한 하늘색으로 자동 배정하지 않는다. 실제 warning/selected/disabled는 색뿐 아니라 명판·선·짧은 이름으로 구분한다. 자재 탭을 펼친다고 고철·목재 재고를 합치지 않는다. [P01](sources.md#p01) [P03](sources.md#p03)

## 7. 추천 실험 순서 — 구현은 별도

가장 먼저 작은 버튼 1개와 왼쪽 사건 카드 1개에서 국소 마스크·취소·한글 가독성을 비교한다. 다음은 정치 화면 1개에서 현재 긴장에 따른 가장자리만 움직이는 안이다. 마지막으로 연구 노드의 선택/진행/완료를 구분하고, 실제 대상 기기에서 단순 알파 방식과 복잡한 방식의 차이를 비교한다.

입력 반응이 좋지 않은 상태에서 전체 의회에 실시간 유체·수많은 파티클·카메라 이동을 한꺼번에 붙이지 않는다. 먼저 정적판이 완전히 기능하고, 효과를 꺼도 같은 결과·정보가 남아야 한다.
