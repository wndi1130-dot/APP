# UI 사운드 — 원작 근거와 우리 게임의 제안 분리

[목록](README.md) · [이벤트 표](event_matrix.md) · [청취 위치](capture_checklist.md)

## 1. 실제 제작팀이 공개한 범위

FP2 공식 Sounds of Frostland에서 음향팀은 도시 소리를 군중·교통·기계층으로 나누고 도시 상태에 맞게 반응시키는 접근을 설명한다. 의회의 대의원 대화와 여러 군중층도 이야기 전달 수단이다. **정치 화면의 주변 소리 층이 상태를 전달한다는 근거**이지 '정치 버튼은 특정 금속음'이라는 cue sheet는 아니다. 이번에는 전사를 읽었고 원본 소리는 직접 듣지 않았다. [G08](sources.md#g08) [G09](sources.md#g09)

작곡가 인터뷰는 Anger 같은 음악을 Fervor가 높아진 사회적 충돌에 연결한다. 음악 변화, 군중 반응, UI 클릭은 시간 규모와 의미가 다르다. 긴장도(Tension)와 Fervor도 같은 이름으로 합치지 않는다. [G11](sources.md#g11)

## 2. FP1 UI 소리를 분석한 자료 — 개발사 공정으로 오인하지 않기

Greg Lester의 독립 분석은 법률서에서 느껴지는 저역·기계 작동·높은 클릭·잔향을 나누고 본인의 재제작을 설명한다. 법 제정 뒤 종, 근무 시작/종료의 나팔을 알림 사례로 든다. 저자 스스로 추정임을 밝혔으며, 이번 연구는 전사/챕터만 읽었다. [G10](sources.md#g10)

따라서 다음은 서로 다르다: (a) 분석자가 들었다고 말한 원작의 특징, (b) 분석자의 자체 재현 재료, (c) 우리 게임의 새 음향 설계. 분석자의 돌 충격·서랍·기계·자물쇠·자갈 조합을 11 bit가 실제 녹음한 재료라고 표기하지 않는다. 영상이 사용한 게임 샘플을 재사용 가능한 CC0 파일로 가져오지도 않는다.

## 3. 우리 게임의 소리 언어 제안

시각적으로 젖은 잉크처럼 보여도 모든 버튼에 물방울·물속 거품을 붙일 필요는 없다. 선택의 의미와 열차의 재료를 기준으로 마른 종이, 목탄 마찰, 닳은 금속 걸림, 가벼운 도면 접촉을 후보로 둔다. 과한 물소리는 실제 물 상호작용으로 오해될 수도 있으므로 청취 비교가 필요하다.

| 층 | 역할(제안) | 주의 |
|---|---|---|
| 짧은 시작점 | 터치·단계 걸림·유효 클릭을 즉시 확인 | 예쁜 잔향이 늦게 시작해 입력 지연처럼 느껴지지 않게 함 |
| 재질 몸통 | 종이/목탄/금속이라는 촉감 부여 | 모든 이벤트를 같은 묵직한 소리로 통일하지 않음 |
| 낮은 무게 | 법안 제출·정치 화면 같은 큰 변화에 한정 | 휴대폰 저역 재생에만 중요한 정보 의존 금지 |
| 짧은 마무리 | 전환이 정착했다는 느낌 | 긴 리버브가 대사·다음 입력을 덮지 않도록 함 |
| 지속 공간 | 의회 웅성거림·기관/바람의 상태 | 매 버튼 one-shot과 별도 관리; 숨은 정보 누설 금지 |

표는 원작의 실제 stem 목록이 아니다. 필요한 음색이 선별·녹음되기 전 cue ID는 의도만 나타내며 실제 WAV 파일 이름이 아니다.

## 4. 소리를 넣을 때와 넣지 않을 때

탭 탐색·호버는 거의 무음 또는 작은 반응부터 비교한다. valid click은 한번, 실패는 다른 짧은 반응, pointercancel에는 성공 소리가 없어야 한다. 연구 항목을 고르는 것·연구 시작·진행·완료는 네 이벤트로 나눈다. 진행률이 한 칸 바뀔 때마다 click을 내지 않는다.

레버는 포인터가 움직일 때마다가 아니라 실제 단계가 바뀔 때만 걸림을 낸다. 법률 제정·부결은 결과가 알려진 뒤 한 번. 화면 재진입·세이브 로드 때 지난 결과음을 반복하지 않는다. 도덕적으로 잔혹한 법의 통과를 승리 팡파르로 자동 해석하지 않는다.

의회의 군중 반응은 단순 메뉴 focus가 아니라 공개된 현재 상태 또는 승인된 장면 이벤트와 연결한다. 비밀 투표에서 특정 공동체 음성/방향으로 숨은 표를 알려주지 않는다. UI의 비세계적 클릭음은 좀비를 유인하는 필드 소음 데이터에 더하지 않는다. 장면 속 무전·실제 기적 등은 기존 게임 규칙이 정한 경우에만 세계 소음과 연결한다.

## 5. 믹싱·이벤트 구조 후보

UI 탐색/입력, 중요한 UI 결과, 긴급 경고, 대사, 공간 루프, 음악의 논리적 그룹을 나누는 안이다. Unity AudioMixer와 snapshot은 이런 상태 전환을 구성하는 공식 도구지만 실제 원작의 middleware 배치라고 주장하지 않는다. [T13](sources.md#t13)

PlayOneShot은 이미 재생 중인 소리를 알아서 취소하지 않는다. UI 연타가 많은 장면에서는 중복 action ID, 짧은 cooldown, 동시 voice 수, 이전 tail 중단/교체 여부를 따로 정한다. 작은 hover가 큰 경고/대사를 끊지 않도록 우선순위를 구분한다. [T14](sources.md#t14)

S1 브라우저는 자동재생 제한으로 AudioContext가 아직 시작되지 않았을 수 있다. 허용된 첫 입력에서 활성화하되, 소리가 준비되지 않았다고 버튼의 시각 반응까지 멈추지 않는다. 백그라운드 복귀·음소거·휴대폰 무음/헤드폰·모노 재생을 실제로 시험해야 한다. [T06](sources.md#t06)

## 6. 재사용 가능한 원본 수급 후보

Kenney의 **Interface Sounds**는 공식 페이지상 100개, **UI Audio**는 50개이고 모두 해당 팩에 CC0 표시가 있다. 버튼·클릭·스위치 계열의 초기 청취 후보로 기록했다. 개별 파일명·포맷·고유 파일 수·종이/도장 포함 여부는 아직 검수하지 않았다. 두 팩 숫자를 '원작 스타일 음원 150개 확보'라고 쓰지 않는다. [A01](sources.md#a01) [A02](sources.md#a02)

최종 종이/연필/래치 느낌이 맞지 않으면 자체 녹음을 비교한다. 각 소리는 초입·몸통·tail을 분리해 필요 없는 부분을 줄이고, UI 의미를 구분할 정도의 작은 변형을 만든다. 사용권 있는 원본, 수정 과정, 녹음자, 출력 형식·채널·레벨, 파일 해시를 남기는 것을 후속 납품 규격으로 제안한다.

## 7. 미확보 사항

FP1/FP2/TWOM 원작의 버튼별 이벤트-파일 매핑, 원본 UI stem, 정확한 filter/EQ 값과 loudness, 모든 연구 완료음의 직접 청취 기록은 없다. 독립 분석과 공개 개발 영상으로 빈칸을 좁혔지만 전체 cue sheet를 복원했다고 주장하지 않는다. 필요한 원작 상황은 capture_plan.json에 비어 있는 관찰 레코드로 남겼다.
