# J11 꼬리칸 수단 시뮬레이션(tail_levers.py) 코드 점검 (2026-10-08)

근거: 문서·시뮬 main 6ee9794 (docs/design/sim/tail_levers.py, s1a_balance.py, first_leg_story.md 6.4·7.7)
묻은 곳: (가)~(다)는 코덱스(높은 추론), 코드 읽기만. (라)는 제가 직접 돌렸다.
물음: (가) 작업조 고르기·솜씨 배율·정차 사망 귀속이 6.4 설명대로인지 (나) 쉼 바닥 계산 (다) 공간 레버의 과밀 반환 (라) 7.7 표 숫자가 다시 나오는지.
제 한 줄 판정: 설명대로 도는 부분이 대부분이고, 버그가 둘 있다. 둘 다 결과를 '덜 아프게' 만드는 쪽이 아니라 하나는 더 아프게(운반 −30%), 하나는 덜 아프게(관계 +1) 만든다. 7.7 표는 지금 코드로 그대로 다시 나온다. 저는 두 버그 줄을 직접 열어 확인했다.

용어: 코덱스가 먼저 정리한 대로, '나간 칸'은 그 정차에 운송조를 낸 공동체(`self.crew`)이고 라이프치히에서 떠난 집단이 아니다. '내준 칸'은 꼬리칸에 자리를 내준 공동체(`self.giver`)다. 같은 칸이 둘 다일 수 있지만 따로 고르고 따로 저장한다.

## (가) 작업조 고르기·솜씨 배율·정차 사망 귀속

- 맞음: `pick_crew()`는 꼬리칸 노출을 먼저 보고 다른 후보의 노출·관계·경비대 조건을 본다. 기관실은 후보에서 빠진다. `stop()`은 고른 칸의 솜씨 배율(꼬리칸 ×1.0, 경비대·의무진 ×0.9, 앞칸 ×0.8)을 곱하고 `finally`에서 되돌린다.
- 맞음: `on_death()`(tail_levers.py 83~86)가 정차 중 죽음을 고른 칸으로 돌리고, 정차 뒤 `self.crew`를 비워 이후 의약품 사망까지 끌고 가지 않는다.
- 버그: s1a_balance.py 303~304. 상위 `stop()`이 실제 운송조와 상관없이 `fervor['tail'] >= 1`이고 `rel['tail'] <= -40`이면 운반량에 ×0.7(꼬리칸 작업 거부)을 곱한다. 운송조를 앞칸으로 돌려도, 쉬고 있는 꼬리칸의 거부가 운반량을 깎는다.
  - 작은 예(코덱스 계산): 앞칸이 나가고 기본 운반 20, 난수·법 배율 1.0이면 솜씨 적용 16이어야 하는데 11.2가 된다.
  - 방향: 그 조건에서 전리품이 의도보다 30% 적다. 관계·이탈 인원에 어떻게 번지는지는 코드 읽기만으로 정할 수 없다.
  - 고칠 안: ×0.7을 `self.crew == 'tail'`(또는 운송조가 꼬리칸일 때)로 묶는다.

## (나) 쉼 바닥

- 맞음. 계산은 `max(min(바닥, 노출), 노출 − 10)`이다. 바닥 위에선 최대 10 내리되 바닥 밑으로 안 가고, 이미 밑이면 그대로다. 꼬리칸 바닥 35에서 60 → 50, 40 → 35, 30 → 30.
- `busy`에 든 칸은 쉬지 않고, 지나친 정차와 허브에서는 모두 쉰다. 경비대·기관실은 바닥 값이 없어 쉼 대상이 아니며, 설명에도 값이 없다.

## (다) 공간 레버

- 맞음: `move(-1)`은 꼬리칸 과밀 +10, 저장된 `giver` 과밀 −10. 마지막 단을 푼 뒤에야 `giver`를 지워서 돌려줄 곳을 잃지 않는다. 예: 꼬리칸/앞칸 75/20 → 두 단 내줌 55/40 → 한 단씩 풀면 65/30 → 75/20. 이미 낸 관계 값은 돌려주지 않고, 설명에도 돌려주는 규칙은 없다.
- 버그: tail_levers.py 119~120. 한 단을 푸는 구간에 바로 `return`해서 129~130줄의 '당겨 둔 동안 단당 −1/구간' 유지 비용을 건너뛴다.
  - 작은 예: 2단·앞칸 관계 −16에서 한 단을 풀면 과밀은 65/30으로 맞게 돌아오지만, 남은 1단의 −1이 빠져 관계가 −17이 아니라 −16으로 남는다.
  - 방향: 2단 → 1단으로 푸는 구간마다 내준 칸 관계가 1 높게 잡힌다. 1단 → 0단은 남은 단이 없어 해당 없다.
  - 고칠 안: 푸는 갈래에서 `return`을 빼고 유지 비용 줄까지 내려가게 한다.

## (라) 7.7 표 다시 내기 (제가 직접 실행)

- tail_levers.py 기본안(새 수단 둘), 정책마다 1000판. 7.7 표 세 줄이 그대로 나왔다.
  - 돌봄: 꼬리칸 도착 관계 −26, 떠나려는 사람 11.0, 실제로 떠난 사람 9.3, 남음 11%·보냄 50%·설득 39%, 앞칸 −8.
  - 방치: −55, 27.5, 27.5, 보냄 100%, 앞칸 +16.
  - 협박: −33(적의 2 이상 74%), 27.6, 10.9, 남음 7%·보냄 20%·무력 73%, 앞칸 −5.
- 즉 표는 지금 코드의 결과이고, 위 두 버그가 들어간 채로 나온 숫자다. 버그를 고치면 표를 다시 돌려야 한다(돌봄·협박은 작업조와 공간 레버를 쓰므로 영향이 있고, 방치는 늘 꼬리칸이라 (가) 버그 영향이 거의 없다고 본다. 이 부분은 추정).
