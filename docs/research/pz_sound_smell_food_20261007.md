# 좀보이드의 소리·냄새·음식 규칙과 모바일 수색 구현안

> 좀보이드 원본 코드는 옮기지 않았고 동작만 설명한다. 코드 블록은 새로 쓴 의사코드다. 위키·소스 링크 일부는 자동 열람이 막혀(403) 대조하지 못했다. 조사 상태: PARTIAL. 이 문서는 조사 기록이며 확정 사항이 아니다. 사진·모델 파일은 저장소에 넣지 않고 링크만 둔다.

조사 기준일은 2026-10-07이다. 공개 웹페이지, 공식 개발 자료, 위키의 판본별 변경 이력, 모드 제작자 설명과 공개 소스 파일을 읽었다. 게임을 실행해 측정한 결과는 아니다. `PARTIAL`은 문서 작성이 끝나지 않았다는 뜻이 아니라, 요청한 일부 반경·시간·최신 판본 규칙을 확정하지 못했다는 뜻이다.

기존 조사와 설계는 `survival_detail.md`, `pz_npcs_combat_weapons.md`, `pz_medical_knowledge_crafting.md`, `field_zombie_ai.md`를 참조한다. 기존 개요와 모드 소개는 재수록하지 않고, 필요한 수치·판본 차이·구현상의 빈칸을 보완한다.

표기의 뜻은 다음과 같다. `[1차]`는 공식 개발 자료나 제작자 자료이며, `[2차]`는 위키 또는 포럼 이용자 설명이다. 공식 포럼에 실린 개발팀 변경 기록도 요청에 맞춰 `[2차·공식 변경 기록]`으로 표시한다. `[모드: 이름]` 뒤에 설명인지 코드인지 구분한다. `[제안]`의 숫자는 우리 게임의 조정 시작값이며, 좀보이드 수치나 현실의 실험값이 아니다.

## 1. 한눈 요약

- 소리는 위치·반경·강도·수명을 가진 사건으로 다루며, 플레이어가 듣는 음향과 좀비 감지 사건을 따로 설계한다.
- M9의 정의상 소리 반경은 Build 41.65에서 40타일, Build 42.0에서 100타일로 바뀌었다. 판본 없는 총기 표는 쓰지 않는다.
- 공식 소리 API에 방 사이와 실내·실외 감쇠 항목이 있다. 벽마다의 정확한 감쇠율과 유인 지속 시간은 확인 못 했다.
- 피 냄새 유인은 Build 41 자료 기준 본게임에 없음으로 정리한다. Build 42의 신규 후각 도입 여부를 확정하는 공식 자료는 확인 못 했다.
- 냄새 모드에는 상처·더러운 붕대 누적 방식과 잔류 경로 방식이 있다. 우리 안은 피 냄새를 별도 사건으로 둔다.
- 음식의 기본 상태는 신선·오래됨·썩음이다. 냉장 5배 연장, Build 41 냉동 25배 연장과 Build 42 완전 냉동 시 부패 정지를 구분한다.
- Build 42에서는 칼·날카로운 돌로 통조림을 여는 규칙이 있으며, 도구와 손을 손상할 수 있다.
- [제안] 필드는 소리·출혈·즉석 섭취 판단을 살리고, 공동 배급·보관·조리·장기 영양은 열차에서 묶어 처리한다.

## 2. 소리

### 2.1. 작동 방식과 확인 범위

공식 모딩 API의 `WorldSoundManager`는 소리 사건에 좌표, 반경, 강도 등을 받는다. 소리 객체에는 수명과 반복 여부가 있고, 좀비별 청각 배율 및 가장 유인력이 큰 소리를 고르는 항목도 있다. 따라서 총소리의 반경 하나만으로 모든 좀비의 반응을 설명할 수 없다. 이 API는 본체의 전체 구현 코드가 아니라 공개된 인터페이스이며, 문서 자체에 정확한 Build 번호가 붙지 않았다. `[1차·판본 미표기]` [소리 관리자](https://projectzomboid.com/modding/zombie/WorldSoundManager.html), [소리 사건](https://projectzomboid.com/modding/zombie/WorldSoundManager.WorldSound.html).

공식 API에는 서로 다른 방 사이와 실내·실외 사이의 감쇠를 나타내는 항목이 있다. **실내외 차이가 전혀 없다고 단정하는 것은 맞지 않는다.** 다만 이 자료만으로 벽을 통과할 때마다 얼마를 깎는지, 재질·두께·문·층 높이가 어떻게 합쳐지는지는 확인할 수 없다. 방 경계 감쇠가 있다는 사실을 정교한 음향 전파 시뮬레이션의 증거로 확대하지 않는다. `[1차·판본 미표기]` [소리 관리자](https://projectzomboid.com/modding/zombie/WorldSoundManager.html).

청각 설정이 실제 유인 판정과 디버그 반경 표시에도 영향을 준다는 점은 Build 41.78 변경 기록으로 확인된다. 따라서 같은 총을 쏴도 청각 설정이 다르면 결과가 달라질 수 있다. 총기의 아이템 정의 반경, 플레이어에게 들리는 음향 거리, 좀비가 실제 반응한 최대 거리를 구분해야 한다. `[2차·Build 41.78]` [변경 기록](https://pzwiki.net/wiki/Build_41.78).

단발 사건이 사라지는 시간과 좀비가 그 지점까지 이동하는 시간도 다르다. 샌드박스의 기억 설정은 보고 들은 대상을 얼마나 추격하는지에 관한 설정이다. 한 번 총을 쏘면 모든 좀비가 정확히 몇 초 동안 따라온다는 공통값은 확인 못 했다. `[2차·Build 42.20.4 문서]` [샌드박스 설정](https://pzwiki.net/wiki/Custom_Sandbox).

### 2.4. Godot에서 짤 방법 [제안]

Godot 4.7.2를 대상으로 설계를 옮길 때, 음향 노드와 감지 관리자 사이의 계약부터 만든다. `AudioStreamPlayer3D`의 거리 감쇠·최대 거리는 청취용 설정이다. 그것만 설정해서 좀비의 감지 규칙까지 구현되었다고 간주하지 않는다. 확인한 문서는 Godot 4 계열의 갱신되는 stable 문서이며, 4.7.2 전용 API·실행 호환성을 검증한 것은 아니다. [공식 음향 노드 문서](https://docs.godotengine.org/en/stable/classes/class_audiostreamplayer3d.html).

총성의 음향은 발사 충격, 기계 작동, 탄피, 실내 잔향으로 나누어 들려줄 수 있다. 초음속 탄의 충격음이나 실내 잔향별 좀비 유인 규칙을 좀보이드에서 확인한 것은 아니다. 우리 게임에서는 발사 한 번당 감지 사건 한 개를 기본으로 두어, 음향 레이어 수만큼 위험이 중복되지 않게 한다. 연발은 짧은 구간의 사건을 합치고 지속 시간만 갱신한다.

아래 거리와 시간은 모두 우리 게임의 시작값이다. Godot 월드의 1단위를 1미터로 정한 경우이며 좀보이드 타일 변환값이 아니다.

| 행동 | 기준 감지 반경 | 사건 수명 / 마지막 지점 조사 시간 |
| --- | --- | --- |
| 웅크려 걷기 / 걷기 / 달리기 | 2 / 4 / 10m | 발걸음 간격으로 발생 / 6초 |
| 조용히 문 열기 / 강제 개방 | 5 / 20m | 1초 / 10초 |
| 창 깨기 | 24m | 2초 / 15초 |
| 근접 휘두르기 / 강한 명중 | 4 / 8m | 1초 / 8초 |
| 권총 / 소총 / 산탄총 | 50 / 90 / 120m | 2초 / 25초 |
| 정상 소음기 장착 권총 | 15m | 1초 / 12초 |
| 작은 라디오 / 경적 / 경보기 | 12 / 80 / 140m | 켜진 동안 갱신 / 종료 후 15초 |

실내는 방·복도·플랫폼·지하 입구를 잇는 소리 전파 그래프로 다룬다. 열린 출입구에는 작은 비용, 닫힌 문과 벽을 통한 누설에는 큰 비용을 준다. 초기 가산 거리는 열린 문 2m, 닫힌 문 12m, 벽 누설 25m로 잡는다. 이는 음향의 물리 단위가 아니라 게임 판정 비용이다. 환기구·계단을 통한 소리 전달과 좀비가 실제로 걸어 나오는 통로는 서로 다른 그래프에 둔다.

```text
소리를_낸다(위치, 종류, 세기):
    청취용_음향을_재생한다(위치, 종류)
    사건 = 감지_사건(위치, 종류별_반경, 세기, 종류별_수명)
    가까운_연발_사건이면_합친다(사건)
    도달_구역 = 전파_그래프를_탐색한다(사건, 거리와_경계_비용)
    도달_구역의_개체와_구역_무리에_사건을_전달한다()

좀비가_사건을_받는다(사건, 전파_비용):
    점수 = 사건.세기 * 거리_감쇠(전파_비용) * 개체.청각
    시각으로_대상을_확인했으면_시각_목표를_유지한다()
    그렇지_않고_점수가_현재_소리보다_크면:
        목표 = 사건이_발생한_지점
        목표_기억_만료 = 현재시각 + 종류별_조사_시간

주기적으로_갱신한다():
    만료된_사건을_제거한다()
    반복_발생기는_켜진_동안만_사건을_갱신한다()
    목표에_도착한_좀비는_정해진_시간만_주변을_조사한다()
    새로운_단서가_없고_기억이_끝나면_기존_생활권으로_돌아간다()
```

위 의사코드는 새로 구성한 설계이며 본게임 코드를 옮긴 것이 아니다. 대상이 소리를 낸 뒤 이동하면 좀비는 마지막 소리 지점을 먼저 조사한다. 소리 사건에 플레이어의 현재 좌표를 계속 붙여 원격 추적하게 만들지 않는다.

모바일에서는 방 그래프의 전달을 사건 발생 때 계산하고, 가까운 개체만 개별 경로를 갱신한다. 화면 밖은 구역별 무리 상태를 갱신한다. 소리는 기존 지하·하수도 개체의 목표를 바꾸며, 새 개체 생성 명령과 합치지 않는다. 기기별 성능 상한은 S22급 실기 측정 후 정한다. 이 문서의 거리·주기만으로 프레임 성능을 보증하지 않는다.

### 3.3. 우리 게임의 피 냄새 규칙 [제안]

피 냄새는 음향과 독립된 `ScentEvent`로 둔다. 소리에 반응하는 좀비의 청각을 낮춰도 후각은 남고, 소음기가 피 냄새까지 줄이지 않는다. 위생은 열차에서 공동 관리하며, 필드에서는 **새로 흐르는 피·젖은 핏자국·오염 붕대**만 위험을 크게 올린다. 일상적인 때나 땀만으로 매 판 씻기를 강제하지 않는다.

피 냄새 점수는 0~100의 게임 값이다. 출혈 강도, 젖은 핏자국, 붕대 상태를 합산하며 실제 출혈량의 밀리리터나 혈액 농도로 해석하지 않는다.

| 단계 | 점수 | 무풍 기준 반경 | 보이는 조짐과 플레이 판단 |
| --- | --- | --- | --- |
| 0. 정리됨 | 0~9 | 0m | 새 출혈이 없고 핏자국도 정리됐다. |
| 1. 옅음 | 10~29 | 6m | 작은 젖은 얼룩과 냄새 아이콘 한 칸을 보인다. 가까운 적에게만 위험하다. |
| 2. 진함 | 30~59 | 14m | 핏자국이 이어지고 아이콘 두 칸을 보인다. 상처 처치나 진로 변경을 고려한다. |
| 3. 강함 | 60~100 | 28m | 피가 눈 위에 계속 떨어지고 아이콘 세 칸을 보인다. 하수도·지하 출입구의 무리가 접근할 수 있다. |

| 요인 | 시작 규칙 | 설계 목적 |
| --- | --- | --- |
| 출혈량 | 약함·보통·심함에 따라 10초당 2·8·16점을 추가한다. 활동성 출혈은 2단계 이상으로 쉽게 올라가게 조정한다. | 피를 많이 흘릴수록 위험해진다는 연결을 보이게 한다. |
| 깨끗한 붕대 | 출혈이 제어되면 해당 상처의 새 냄새 배출을 멈춘다. 기존 옷·바닥의 피는 남는다. | 붕대와 세척이 서로 다른 문제를 해결하게 한다. |
| 더러운 붕대 | 해당 상처의 맨상처 배출량의 25%를 남긴다. | 갈아 주면 위험이 줄지만 계속 교환하는 잡무는 피한다. |
| 간단히 닦기 / 씻기 | 옷·피부에 남은 냄새 점수를 각각 60% / 90% 줄인다. 지속 출혈의 배출량은 줄이지 않는다. | 씻었는데 계속 출혈해 즉시 위험이 돌아오는 이유를 설명한다. |
| 바람 | 풍하측 반경 1.5배, 풍상측 0.6배, 옆 방향 0.9배로 길게 편다. | 풍향을 보고 우회하는 결정을 만든다. 강풍이 모든 방향 반경을 늘리지는 않는다. |
| 영하의 추위 | 공기 중 유효 반경을 0.6배로 낮춘다. | 겨울의 작은 이점을 준다. 실제 냄새 물리 모델을 주장하지 않는다. |
| 새 눈이 흔적을 덮음 | 덮인 경로 노드 세기를 0.7배로 낮춘다. | 눈을 활용한 이동 판단을 준다. 피가 사라진 것처럼 처리하지 않는다. |
| 얼어붙은 핏자국 | 즉시 배출은 약하게 하되, 오염 흔적은 더 오래 남긴다. | 추위의 확산 억제와 흔적 보존을 구분한다. |
| 실내·지하 | 닫힌 공간 사이 전달은 출입구·환기 연결로만 계산한다. | 콘크리트 바닥을 사이에 두고 모든 지하 좀비가 동시에 알아채는 일을 막는다. |

필드 경로 노드는 이동 2m 또는 실제 시간 10초마다 남기고, 평상시 60초·얼어붙은 흔적 120초 뒤 제거하는 값으로 시작한다. 갱신은 1초마다 활성 노드만 처리한다. 풍향이 바뀌면 전파 모양을 다시 계산한다. 누적 반경과 노드 수에는 상한을 둔다. 이 값들은 모드 기본값과 무관하다.

```text
피_냄새를_갱신한다(사람):
    배출 = 제어되지_않은_출혈 + 젖은_피의_잔류량 + 오염_붕대의_배출
    단계 = 냄새_점수를_단계로_바꾼다(배출)
    공기_도달범위 = 단계별_반경 * 추위_배율 * 풍향별_배율
    경로_조건을_만족하면_현재_위치에_흔적_노드를_남긴다()
    공간_연결을_통해_도달한_좀비에만_냄새_단서를_전달한다()

좀비가_냄새를_받는다(흔적):
    눈으로_확인한_대상이_없으면:
        목표 = 도달_가능한_가장_강한_흔적의_위치
    흔적_조사중_새_냄새를_찾지_못하면_수색을_끝낸다()
```

조짐은 위협의 방향과 원인을 보여 주어야 한다. 얼어붙은 야외에서는 파리를 기본 표시로 쓰지 않는다. 파리는 난방되는 지하실·실내의 시체 주변 연출로 제한한다. 까마귀는 시체나 먹이 주변의 분위기 단서로 쓰되, 캐릭터 냄새의 정확한 측정기처럼 쓰지 않는다. 캐릭터의 젖은 얼룩, 눈 위 핏방울, 붕대의 색, 짧은 풍향 표식과 단계 아이콘이 기본 단서다. 이는 좀보이드의 규칙이나 생태학적 관찰값이 아닌 연출 제안이다.

## 4. 먹을 것

### 4.1. 신선도와 기간

좀보이드 음식의 기본 신선도는 **신선 → 오래됨(stale) → 썩음(rotten)**이다. 별도의 보편적 네 단계 체계는 확인되지 않는다. 요청한 오래됨·상함·썩음의 네 단계 UI는 우리 게임에서 추가할 수 있지만 본게임 상태명으로 설명하지 않는다. 날짜도 신선 기간과 그 뒤의 기간을 더하는 방식이 아니다. `DaysTotallyRotten`은 신선 기간을 포함한 누적 부패 시점이다. `[2차·B42.20.0 문서]` [음식](https://pzwiki.net/wiki/Food).

### 4.4. 칼로리·체중

공식 영양 API에는 칼로리·탄수화물·지방·단백질, 활동별 소비와 체중 증가·감소 상태가 따로 있다. **허기를 채우는 값과 장기 체중을 유지하는 값은 같은 척도가 아니다.** `[1차·판본 미표기]` [영양 API](https://projectzomboid.com/modding/zombie/characters/BodyDamage/Nutrition.html).

Build 42.21.0 영양 위키는 기본 시작 체중을 80으로, 정상 구간을 75.1~84.9로 제시한다. 체중 상태는 이동·지구력·체력 경험 등에 영향을 준다. 체중 증가의 칼로리 임계치는 현재 체중과 대사 특성에 따라 달라지므로, 오래된 특정 칼로리 숫자를 모든 캐릭터의 하루 필요량으로 고정하지 않는다. 활동은 축적 칼로리를 소비한다. `[2차·B42.21.0]` [영양](https://pzwiki.net/wiki/Nutrition).

### 4.5. 우리 게임의 음식 규칙 [제안]

필드에서 음식마다 날짜·열량·기분을 전부 계산하게 하지 않는다. 가방 카드에는 **먹을 수 있나, 바로 먹나, 데워야 하나, 공동 배급에 얼마를 더하나**가 먼저 보인다. 세부 정보는 펼쳐서 본다. 멸망 뒤 여섯 번째 겨울이라는 설정상 오래된 상점에서 평범한 생식품이 신선하게 나오는 생성 규칙은 피한다. 최근 사냥·생산·반입, 정상적으로 유지된 저장고 같은 출처를 붙인다.

다음은 네 단계 UI를 원할 때의 예시다. 모두 우리 게임의 게임 시간이며 좀보이드의 기간을 옮긴 값이 아니다.

| 음식군 | 신선 끝 / 오래됨 끝 / 썩음 시작 | 중간 상태와 사용법 |
| --- | --- | --- |
| 최근 얻은 생고기 | 12 / 18 / 24시간 | 신선해도 가열 전 위험하다. 18~24시간은 상함으로 표시하고 배급에서 제외한다. |
| 열차에서 만든 스튜 | 8 / 12 / 16시간 | 즉시 배급·보온·냉각 중 하나를 선택한다. |
| 빵 | 48 / 72 / 96시간 | 오래됨은 맛·사기 손해, 상함은 폐기 우선 대상으로 둔다. |
| 밀봉 통조림·건조 배급 | 날짜 노화보다 밀봉·습기·오염 상태를 우선한다. | 정상 밀봉은 장기 비축용이다. 손상·팽창·침수는 별도 검사 상태로 표시한다. |

배치 신선도는 게임 시계의 경과를 따라 진행한다. 실제 20분이라는 판 길이를 그대로 20분의 부패 시간으로 쓰거나, 반대로 판이 시작될 때마다 모든 가방 음식을 새것으로 초기화하지 않는다. 필드가 시작·끝나는 시점의 시계를 저장해 열차와 같은 시간축을 쓴다.

```text
식량_배치를_갱신한다(배치, 지난_게임시간):
    배치.노화 += 지난_게임시간 * 보관상태별_진행률
    배치.신선도 = 음식군별_임계치로_판정한다(배치.노화)

가방에서_열차로_인계한다(배치):
    나이와_밀봉과_오염과_조리상태를_보존한다()
    같은_조건의_배치와만_합친다()
    나이를_평균내어_오래된_음식을_새것처럼_만들지_않는다()

열차에서_조리한다(선택한_재료):
    재료와_연료와_작업량을_먼저_확인한다()
    작업_결과는_이동구간_정산에서_반영한다()
    가장_위험한_재료의_오염과_신선도_손해를_계승한다()
    가열로_제거할_수_있는_위험만_제거한다()
    완성_음식은_새_조리시각과_계승한_위험을_함께_저장한다()
```

배급 자동 선택은 안전 판정을 먼저 한다. 상한 음식은 공동 배급에서 제외하고, 사용자가 강제로 먹는 예외 선택에만 결과를 표시한다. 필드에서 위험 음식을 먹으면 다음 정차까지의 병 상태·행동 손해로 연결하되, 예고 없는 즉사와 장기간 조작 불능은 기본 규칙에서 제외한다. 상세 발병 시간과 손해 수치는 플레이 테스트로 정한다.

뺄 것은 필드의 세부 영양소 계기판, 매 식재료의 손질 대기, 지속적인 개인 설거지·세척 요구, 요리 기술에 의한 썩은 재료 무제한 복구다. 남길 것은 총을 쏠지, 상처를 감쌀지, 지금 먹을지, 따개 없이 열지, 무거운 식량을 공동 창고로 가져갈지의 결정이다.

## 5. 참고한 모드·오픈소스

모드 설명의 B41/B42 지원 표시는 제작자의 대상 표기이며, 해당 판본에서 직접 실행해 확인한 호환성 보증이 아니다. 공개 열람과 우리 게임으로의 코드·이미지·음향 재배포 권한은 서로 다르다.
