# 빌드와 해 보는 법

기준: 2026-10-10 · [핸드북 입구](README.md)

## S1 정치 웹 빌드 (S1a + S1b + S1c)

- **해 보기(2026-10-10부터):** PC에서 판을 띄우고 같은 와이파이의 폰으로 접속한다(사용자 결정). 아래 '내 컴퓨터에서'의 명령을 쓰고, 폰을 가로로 든다. 손질한 판이 준비되면 작업 세션이 접속 주소를 사용자에게 알린다.
- **예전 링크:** claude.ai에 올린 플레이 빌드 [S1a 열차 정치](https://claude.ai/artifact/4cbKmJX3VRBakLZDi9NQnE)는 비공개 링크라 소유자만 열린다. 마지막 판은 v10(main b042d12, 사건 20장 꺼짐)이고 사용자가 H6를 이 판으로 해 봤다. 이 링크는 클라우드에서만 고칠 수 있어 로컬에서는 바꾸지 않는다. 더 옛 계정의 링크(v22)는 열리지 않는다.
- **아티팩트로 다시 올리기(클라우드 때의 방법, 지금은 쓰지 않는다):** `cd s1 && npm ci && npm run build` 뒤 `dist`의 js·css를 html 한 장에 넣고(doctype·html·head·body 태그는 뺀다, 게시할 때 틀이 붙는다) claude.ai 아티팩트로 게시한다. 사용자가 해 보는 동안에는 같은 링크를 바꾸지 않는다.
- **내정 켜기:** 메뉴의 '내정 켠 새 판', 또는 주소에 `?s1c=1`. 이 판이 H6 판정용이다. H6는 2026-10-10에 '손질 필요'였고, 다음 판에는 이동 사건 20장(PR 102, 지금 main에서는 기본 꺼짐)을 켠다(같은 날 사용자 결정).
- **어두운 길:** 코드에는 있지만 기본으로 꺼져 있다. 켜기 전 고칠 것(K02 열하나)은 다 고쳤고(PR 46·47·53) 켠 판 시뮬레이션의 H7 줄도 붙었다(PR 58). 사용자 H7 판정은 아직이다. 계엄 시험 시작 상태는 주소에 `?s1b=1&scene=powers` 또는 `?s1b=1&scene=martial`(PR 87).
- **같은 판 다시:** 주소에 `?seed=글자`. 메뉴에 같은 시드로 처음부터, 새 판, 숨은 수치 보기(테스트용)가 있다. 처음 한 판은 숨은 수치를 끄고 하길 권한다.
- **한 판 흐름:** 출발 전 칸을 눌러 난방·배급 레버를 맞춘다 → 달리며 서류 카드를 처리한다 → 정차에서 노릴 것·머물 시간·보낼 사람을 고른다 → 3구간마다 의회에서 거래하고 레버로 표결한다 → 24구간까지 가거나 좌초·축출·반란으로 끝난다.
- **내 컴퓨터에서:** `cd s1 && npm ci && npm run dev`(같은 와이파이의 폰은 `npm run dev -- --host`). 자세한 건 [s1/README.md](../../s1/README.md).

## S2 필드 회색 상자

- **받기:** GitHub Actions의 **S2 Android field graybox** 성공 실행에서 `s2-android-debug-<번호>`를 내려받아 안의 `s2-field-debug.apk`를 깐다. 빌드마다 디버그 키가 바뀌어 이전 앱을 지우고 깐다. 받은 파일은 2주쯤 뒤 만료된다.
  - [빌드 47](https://github.com/wndi1130-dot/APP/actions/runs/37986929356): H3를 통과한 판(2026-10-10 판정, 폰 S22). 무거움 기본, K03 고침과 부위별 상처 모델이 들어 있다.
  - 그 뒤 main 빌드에는 셰이더 잇기, 층 찾기(PR 103), 리뷰 고침(PR 100·105)이 들어 있다. H3 의견 조작 묶음(PR 108)이 합쳐진 뒤의 main 빌드가 다음 확인용이다.
  - 옛 판: [빌드 37](https://github.com/wndi1130-dot/APP/actions/runs/37679568917)(관성 기본 '중간'), [빌드 39](https://github.com/wndi1130-dot/APP/actions/runs/37708417877)(무거움 기본, PR 44). 받은 파일 보관 기간이 지나면 내려받을 수 없다.
- **한 판:** 시작 화면에서 설정을 고르고 내린다 → 승강장에서 동료 셋과 내린다 → 실제 20분까지 안전, 30분이 끝 → 승강장에서 출발을 누른다. 끝 화면의 '영수증 복사', '기록 복사'를 눌러 메모해 두면 피드백에 쓰인다.
- **H3 세 판:** 1) 마음대로 2) 조용히(근접, 웅크림, 활 엄호, 급수탑은 눈 녹이기) 3) 시끄럽게(산탄총, 문 차기, 급수탑 불, 약탈자와 싸움). 판정은 통과 / 고쳐서 다시 / 실패.
- **조작 요지:** 왼손으로 화면 왼쪽을 끌면 스틱, 오른쪽에 조준(누르고 있다 떼면 쏨)·공격(한 번 누르면 근처가 빌 때까지)·밀치기·상황 단추. 잡히면 '밀쳐!'를 1.5초 안에. 전체 표는 [s2/README.md](../../s2/README.md) '조작'.

## 테스트와 CI

| 대상 | 무엇이 도나 | 어디서 |
|---|---|---|
| S1 웹 | 타입 검사, vitest(규칙 자동 플레이, 결정성, 저장, 금지어, 영수증 계약 포함. main 기준 1,210개), 프로필·데이터 검사, Vite 빌드, 화면 22장 넘김 검사 | `.github/workflows`의 **S1 web checks** |
| S2 Godot | GUT 테스트 402개(테스트 함수 수와 돌린 수가 같은지도 검사), 안드로이드 APK 빌드 | **S2 Android field graybox** |

둘 다 지금 초록이다. 테스트 개수는 2026-10-10 main(e3af560)의 CI 기록이고 계속 는다. 예전에 이 표에 적었던 '시드 7 자동 판 30분'은 지금 워크플로와 `s2/tests`에 없어 뺐다.

S1과 S2를 잇는 정차 영수증은 한 스키마(`s1/schema/receipt.schema.json`)와 판정표(`s2/tests/game/fixtures/receipt_contract_cases.json`, 변형 영수증 31줄)로 묶여 있다. 같은 영수증을 S1 vitest와 S2 GUT가 같게 판정하는지 보고, 규칙을 바꾸면 이 표에 줄을 더해 양쪽을 함께 맞춘다. 공용 프로필 스키마의 id 목록(특성, 직업, 이름 언어)도 계약 테스트로 문서와 묶여 있다.

액션은 Node 24 판으로 올렸다(PR 56). 클라우드 세션은 Godot을 내려받지 못해 Godot 빌드와 테스트가 GitHub Actions에서만 돌았다. 로컬 세션은 PC의 Godot 4.7.2로 GUT를 돌릴 수 있고(GUT는 CI와 같은 판을 받아 쓰고 커밋하지 않는다), APK는 여전히 Actions가 만든다. 시뮬레이터(파이썬)는 [docs/design/sim/](../design/sim/)에 있다.

## 성능

갤럭시 S22에서 회색 상자로 쟀다: 좀비 150마리, 시야·안개·비·그림자를 켜고 10분 동안 109~111fps, 평균 프레임 약 9ms, 열로 느려지지 않음. 실제 게임은 30이나 60fps로 묶는다. 텍스처·뼈대가 붙은 실제 모델로는 아직 안 쟀다. 기록: [s2/PERF_CHECKLIST.md](../../s2/PERF_CHECKLIST.md), [engine.md](../design/briefs/engine.md) 8장.
