# S3 출발 계약과 귀환 영수증

작성: 2026-10-25 · 상태: 꼴은 이 문서로 정함(기존 결정 안), 새 값이 드는 넷은 결정 카드로 묻는 중(7절) · 앞 문서: [S3 첫 시험 범위](s3_first_trial_scope.md) 4절 「출발 명세와 귀환 결과」, [몸과 부상](body_injury.md) 4.1·4.6·5장

열차와 필드는 이 두 문서로만 이어진다. 열차가 정차마다 **출발 계약**을 한 장 내고, 필드는 그 계약을 받아 정차를 열며, 끝나면 **귀환 영수증**을 한 장 돌려준다. 열차는 영수증을 한 번만 반영한다. 지금까지는 필드 쪽이 기본 분대와 표본 출발 명세로 나가고, 열차 쪽 특별 회기와 둘째 역은 표본 파일을 읽었다. 이 문서는 그 표본 자리를 실제 판 상태로 바꾸는 꼴을 정한다.

## 1. 지금 끊긴 곳

| 끊긴 곳 | 지금 | 이 문서 뒤 |
|---|---|---|
| 필드가 누구로 나가나 | 기본 분대 넷(명부에 없는 id)과 고정 기술·장비 | 계약의 명단. 열차 명부의 같은 사람(같은 id) |
| 영수증이 열차에 닿나 | 필드 영수증은 id·출발·상징물·약속을 안 적어 판 2로 나간다. 열차는 판 4만 받는다 | 필드가 계약의 id로 판 5 영수증을 낸다 |
| 회기와 둘째 역 | 표본 파일의 상태(`field_vectors.json`)를 읽는다 | 귀환을 반영한 그 판 상태로 연다 |
| 상처 | 필드는 부위·종류·곪음을 적지만 열차가 등급·부위를 다시 뽑는다 | 필드에서 적은 부위·종류·처치·곪음 그대로(3절) |
| 열차의 몸 상태 | 허기·근육통은 필드에 자리만 있고 값이 안 온다 | 계약이 사람마다 허기·근육통·휴식·상처를 싣는다 |
| 앱 중단 | 몸 타이머·체온·난수 진행·무리·임무는 저장하지 않는다 | 6절 |

## 2. 출발 계약 (판 2)

열차(S1 기준 구현, Godot 이식은 같은 값)가 정차 고르기에서 「내리기」를 누를 때 판 상태에서 만든다. 판 1(`s1/src/game/field_receipt.ts` FieldDeparture)의 칸은 그대로 두고 사람 칸을 넓힌다. 판 1 계약도 계속 읽는다(시험 표본).

```
{ version: 2, departureId, stopId, placeId, segment, arriveMin?, domestic,
  promises: [ {id, kind, madeTo, label, subjects} ],      // 판 1과 같음
  roster:   [ Person ],      // 처음부터 나가는 수색대(열차장 + 동료)
  workCrew: [ Person ],      // 작업조 부르기로 내려올 수 있는 사람(운송조·호위조)
  train:    { food, hungerSegs, cold, weather,
              ammo?: {pistol, shell, craft}, lures? } }  // 정차 전체에 걸리는 열차 사정, 탄·미끼는 열차가 재고로 둘 때만
Person = { id, comm, name, role: chief|companion|carrier|escort,
  body:  { strength, melee, shooting, stealth, search },  // 몸 능력 0~10 (결정 카드 A)
  know:  { field, skill } | null,                          // 지식 층(내정 명부의 분야·등급)
  wounds:[ { woundId, part, grade, state, daysLeft, septic } ],  // 열차 명부의 활성 상처
  hunger: 0|1|2, sore: 0|1|2, rest: 0|1|2,                 // 결정 카드 B
  gear:  { hands: [[id, quality, condition]], items: {id: n}, wear: {place: id | {id, condition, holes?} | ""}, bag },
  rel,                                                     // 그 칸과 열차장의 관계
  stance?: good|bad, cues?: [key] }                        // 열차장에 대한 그 사람의 기억(사람 기억 줄기, 없으면 칸 관계만)
```

- **id는 열차 명부의 id다.** 이름 있는 사람은 프로필 id(`p_001`…), 열차장은 명부 밖의 고정 id `captain` 하나다. 필드는 이 id를 끝까지 바꾸지 않고 영수증의 사람 목록·상처·목격에 그대로 쓴다. 기본 분대(`p_guard_marek` 등)는 열차 없이 필드만 여는 시험 입구에만 남는다.
- **수색대**: 열차장과 동료 셋이 기본이다. 동료 후보는 그 구간에 나갈 수 있는 사람이다(S1 `crewNames`와 같은 거름: 16~65세, 정찰조로 다녀온 사람·앓는 대표·근신·경비·깊은 상처 이상인 사람 제외). 출발 화면이 후보 가운데서 고르게 하고, 기본은 칸마다 한 사람(경비대·의무진·꼬리칸, 지금 기본 분대의 칸 구성)이다.
- **작업조**: 이름 있는 공동체 사람이다(몸과 부상 5장). 운송조는 S1 정차의 작업조(`stopCrew`: `crewComm` 칸에서 `crewSize`명), 호위조는 경비대에서 둘이다. 필드에서 부르기 전에는 열차에 있고, 부르면 그때 영수증 `people.sent`에 든다.
- **장비는 묶지 않는다.** 결정 407 C1(장부 한 곳)대로 출발 때 열차 재고에서 빼지 않는다. 쓴 탄·잃은 무기는 귀환 때 순증감으로 돌아온다. 무기·탄을 열차 재고에서 고르는 화면은 파밍 손맛 줄기(결정 426) 몫이고, 그 전까지는 역할별 기본 장비를 싣는다. 열차가 무기고·탄·옷장을 재고로 두면(S2 `train_dom.gd`, `kit_pick.gd`) 역할 장비를 무기고에서 집고(같은 것 → 같은 종류 가장 좋은 상태 → 빈손), 탄은 `train.ammo`로 넘기며(필드는 총부터 채우고 나머지가 공동 탄), 열차장과 동료의 겉옷·장갑은 옷장에서 꺼내 상태·구멍 그대로 입힌다(비면 `""` = 외투 없이, 작업조는 기본 차림, 결정 443). 재고에서 빼지 않는 것은 같다 — 줄어드는 것은 귀환의 순증감(J01). 무기고·탄·옷장 칸이 없는 열차(S1의 상태)는 기본 장비 그대로다.
- **도착 시각** `arriveMin`(0시부터 분, 결정 471 B0): 열차가 판 씨앗과 구간으로 굴린다(S1 `stop_time.ts`, 아침 40·한낮 35·늦은 오후 20·해 질 녘 5%, 10분 단위 — S2 `field_clock.gd`의 띠와 같다). 노선표가 도착 전에 같은 값을 보이고, 필드 시계·정차 장면이 이 값에서 시작한다. 없던 계약은 10:30.
- **약속**은 판 1과 같다. 서막 약속은 판 상태의 `story.flags`와 서막 운반조에서, 교대 약속은 그 칸에 걸린 `skip_dispatch` 약속에서 만든다.
- **동시 점유 금지**(첫 시험 범위 4절): 계약에 든 사람은 그 구간에 공방·가르치기·침상에 없다. 수색대는 정차 시작부터, 작업조는 불린 뒤부터.

## 3. 귀환 영수증 (판 5)

판 5 = 판 4 + 사람마다의 끝 상태(`crew`) + 상처의 처치 + 열차 방어(`defense`). 판 4 영수증도 계속 받는다(시험 표본, 자동 정차).

```
people.wounds: [ {person, part, kind, festering?, treat?: {bandaged, disinfected,
                  sutured, splinted, tourniquet, pulled, quick}} ]
crew:   [ {person, exhaustion: 0|1|2, hunger: 0|1|2, bodyUse: {melee: n, …},
           gearBack: {hands, items, wear?}} ]  // 살아서 열차에 오른 사람만
defense:{ held: bool, people: [ids], hurt: [ids], dead: [ids],
          wounds: [ {person, part, kind, festering?, treat?} ] } | null
witnessed: [ {…, template?} ]               // 판 4와 같음. template 이름 표는 4절
wardrobeIn?: [ Garment ]                    // 승강장에서 열차에 실은 옷장 자리 옷
luresBack?:  {id: n}                        // 남은 미끼
foodIn?:     {id: n}                        // 열차에 실은 음식, 녹이기 전 이름별(J07)

Garment = { id, condition: 0~1, holes?: {부위: true} }
wear    = { jacket: Garment|"", hands: Garment|"", coat?: Garment|"" }   // "" = 맨몸
```

- **사람 목록**(sent·injured·bitten·dead·missing·leftBehind·rescued)은 판 4 그대로다. 단 `sent`는 `roster` 전부에 불린 `workCrew`를 더한 것과 같아야 한다(판 4는 `roster`와 똑같아야 했다).
- **상처 줄 하나가 필드의 상처 하나다.** 부위 여섯(`head_neck`·`torso`·`arm_left`·`arm_right`·`leg_left`·`leg_right`), 종류 일곱(`scratch`·`laceration`·`deep`·`embedded`·`bite`·`fracture`·`amputation`). `amputation`은 필드에서 자른 팔·다리의 남은 자리이고 팔·다리 네 부위에만 온다(J05). `treat`는 그 상처에 해 둔 처치이고 `quick`는 의료 지식 견습 이상이 다친 지 실시간 2분 안에 처치한 것(몸과 부상 4장 「빠른 처치」)이다.
- **열차 방어**는 정차 소리 줄기(결정 416)가 채운다. 방어에 선 사람은 계약의 명단이 아니라 열차에 남은 사람이라 `people`과 따로 둔다. 상처는 같은 꼴, 같은 반영(4절)이다.
- `crew.bodyUse`는 필드에서 몸 능력을 쓴 양이다. 쓰면 오르는 규칙(field_unified 3장)이 들어올 자리이고, 그 전까지는 비어 있다.
- **장비 귀환**(출발 때 빼지 않은 장비의 순증감, 2절): `gearBack.wear`는 그 사람이 입고 돌아온 옷장 자리 옷이다. 출발 `gear.wear`와 같은 꼴이고, `coat`는 필드에서 주워 입은 긴 외투가 있을 때만 쓴다. `wardrobeIn`은 승강장에서 실은 옷장 자리 옷(재킷·외투·장갑)이고 셔츠 같은 것은 넣지 않는다. `luresBack`은 미끼가 나갔을 때만 쓴다. 세 칸 다 없어도 된다(판 5 앞쪽 영수증).
- **실은 음식**(J07): `foodIn`은 열차에 실은 음식을 녹이기 전 필드 물건 id(`meat_spoiled`·`can_dented` 등, 상태가 id에 들어 있다)별 개수다. `stock.food`를 쪼갠 내역이지 더할 몫이 아니다: 열차는 식량을 지금처럼 `stock.food`로만 더하고, 솥이 `foodIn`의 id로 신선도·익힘·밀봉을 읽는다. 없으면 이름 없는 식량으로 센다.
- 열차는 이렇게 맞춘다. 탄 = 출발 전 − 계약 `train.ammo` + `stock.ammo_*`. 무기고 = 나간 `gear.hands` − 돌아온 `gearBack.hands`. 옷장 = 나간 `gear.wear` − 돌아온 `gearBack.wear` + `wardrobeIn`. 미끼 = 출발 전 − 계약 `train.lures` + `luresBack`. `gearBack.wear`가 없으면 나간 그대로 돌아온 것으로, `luresBack`이 없으면 다 쓴 것으로 센다. 죽거나 남겨져 `crew`에 없는 사람의 무기·옷은 잃은 것이다.

## 4. 열차가 영수증을 반영하는 법

차례는 판 4와 같다: 검사 → 물자 → 사람 → 상처 → 약속 → 목격. 같은 영수증 id는 한 번만(결정 296, 시험 T07). 바뀌는 것은 상처와 몸 상태다.

**상처는 다시 뽑지 않는다**(첫 시험 범위 4절 「직접과 자동이 같은 계약」, 시험 T06). 필드가 적은 값을 아래 표로 열차 명부에 옮긴다. 몸과 부상 4.1·4.6의 「열차로 돌아가면」을 표로 옮긴 것이다.

| 필드 상처 | 열차 명부 |
|---|---|
| 절단 | 절단(`amputation`), 같은 부위. 침상 4일 뒤 그 팔·다리는 돌아오지 않는다 |
| 골절 | 골절(`fracture`), 같은 부위. 빠른 처치로 부목을 댔으면 가벼운 상처(`light`) |
| 깊은 상처, 박힌 것 | 깊은 상처(`deep`), 같은 부위 |
| 긁힘·찢김뿐 | 기록하지 않는다(한 구간 안에 낫는다). 단 출혈 심함·쓰러짐으로 `injured`에 든 사람은 카드 C |
| 물림 | 부상이 아니라 물린 사람(`bitten`). 열차의 물림 규칙(숨은 물림, 2구간)으로 간다 |
| 곪음 | 곪음(`septic`)을 그대로. 굴리지 않는다 |
| 부위 | `head_neck`→`head`, `torso`→`torso`, `arm_left`→`armL`, `arm_right`→`armR`, `leg_left`→`legL`, `leg_right`→`legR` |

- **사람마다 기록 하나**다. 열차의 부상자 수와 침상은 사람을 센다. 한 사람이 무거운 상처를 여럿 가져오면 가장 무거운 것(절단 > 골절 > 깊은 상처)이 등급·부위가 되고, 나머지는 그 기록의 `field` 칸에 그대로 붙어 의무칸 화면이 읽는다.
- 낫는 날 수는 S1 표(결정 055)대로다. 깊은 상처의 3일/4일만 지금처럼 그 사람·그 구간으로 정해진 동전이 고른다(등급·부위·곪음은 굴리지 않는다). 처치가 날 수에 닿게 할지는 카드 C.
- 열차장이 다쳐 오면 같은 명부에 열차장으로 오른다(S1 `hurtCaptain`과 같은 꼴).
- **몸 상태**: `crew`의 탈진·허기는 그 사람의 다음 출발 계약 `rest`·`hunger`로 이어진다(카드 B).

목격 template 이름(사람 기억 줄기가 쓴다, 스키마 키는 늘지 않는다): `body_search`(있음), `rescued_from_grab`, `carried_back`, `treated_by`, `left_behind_survived`, `spared_raider`, `shot_surrendered_raider`, `resident_aid`, `resident_robbed`, `resident_ignored`. 목격자는 `roster`·`workCrew`·`rescued`의 id만 쓴다. 반영 끝의 사람 기억 갈무리는 사람 기억 줄기가 붙인다.

## 5. 회기와 둘째 역

귀환을 반영한 판 상태(정차 고르기에서 들고 간 그 판)가 그대로 특별 회기를 열고(결정 290·303), 회기를 닫은 상태가 열차 턴으로 다음 구간을 달려 둘째 역 도착 화면과 끝 카드를 만든다(결정 297). 표본 파일은 시험만 읽는다. 결정 382의 고정 매핑(목재 → 난방 배당 표 → 다음 파견)은 이 판 상태 위에서 그대로 돈다.

같은 시작에서 가져온 것·구한 사람·지킨 약속이 다르면 회기 후보·표·둘째 역 화면이 달라야 한다. 이것이 J01의 받아들임이고, 시험은 같은 씨앗에서 영수증 셋(목재 있음/없음, 약속 지킴/어김, 사람 하나 잃음)을 넣어 셋이 서로 다른 회기·도착을 내는지 본다.

조각의 판은 S1 새 판(`createGame`)을 자산 `s2/game/train/slice_start.json`으로 내보낸 것이다(`s1/tools/slice_vectors.ts`). 조각은 이 판을 2구간에 두고 열차 턴(`train_advance.gd`, S1 그대로)으로 첫 정차까지 달린다. 열차 서류는 조각에 아직 화면이 없어 걸음마다 비운다(S1 `field_arrival.test.ts`의 조각과 같다). 차례는 첫 정차 → 출발 계약 → 필드 → 영수증 반영 → 특별 회기(보통 안건은 `council_agenda.gd`) → 표결·회기 닫기 → 열차 턴으로 둘째 역 → 끝이다.

필드가 정차를 대신 나가므로 열차는 `resolveStop`을 부르지 않는다. 영수증을 반영할 때 정차 단계이고 정차가 아직 안 끝났으면 그 정차를 **필드 결과로 닫는다**(S1 `closeFieldStop`, S2 `field_return.gd` `_close_field_stop`, 결정 카드 s3-link 2026-10-26 F를 결정 442로 추천 적용). 굴림은 없다. 정차마다 같은 것(장작더미, 돌아온 사람의 자리비움, 가장 많이 나간 칸 말고는 쉼, 정차 약속 확인)은 파견과 같이 세고, 체류 석탄·위험·전리품·부상·사망·구조·물림은 영수증이 이미 적었으니 다시 세지 않는다. 내정 정차 훅(`domesticStop`)은 내정 줄기가 붙인다.

맞대기 시험(`s2/tests/train/test_slice_vectors.gd`)은 같은 계약에 영수증 셋(가져옴 많음 / 빈손에 한 명 다침 / 한 명 죽음)을 넣어, 첫 정차·계약·반영·회기 후보·표결·둘째 역 걸음·도착 화면·끝까지 S1과 판 상태 전체가 같은지, 그리고 셋이 서로 다른 회기 후보나 둘째 역을 내는지 본다. S1 새 판에는 서막 약속이 없어 약속 지킴/어김 갈래는 서막을 거친 판이 들어올 때 더한다. 둘째 역 화면의 수는 소수 첫째 자리까지 적는다.

## 6. 앱 중단 뒤 같은 위기로

단일 칸 자동 저장(결정 296)에 지금 빠진 것을 더한다. 기준은 「끄고 켠 뒤 1초가 끄지 않은 1초와 같다」다.

| 더하는 것 | 지금 |
|---|---|
| 몸: 상처마다 피·붕대 시각·감염 창 시계, 출혈·쓰러짐 시계, 숨, 체온·젖음, 통증·진통제 | 상처 목록·감염 표식·탈진만 |
| 난수의 지금 걸음(씨앗이 아니라 상태) | 씨앗만 |
| 망자의 하던 일(쫓는 대상 id, 잡기·덮치기 남은 시간), 무리(가는 곳·남은 길), 감독관 예산 | 하던 일은 배회로 바뀌고 무리·예산은 버림 |
| 문·창 상태(열림·잠김·판자·깨짐) | 일부(spots) |
| 임무·버티기 판 진행, 동료에게 준 명령 | 버림 |
| 정차 중 새로 생긴 더미(해체 부산물, 죽은 사람의 짐) | 지도에 없는 것은 버림 |

- 저장은 상태를 그대로 적고, 불러올 때 아무것도 다시 굴리지 않는다. 그래서 중단을 되풀이해도 얻거나 잃는 것이 없다.
- 잡혀 있는 동안 끊겼다 돌아올 때 입력 준비 시간을 줄지는 카드 D.

## 8. 맞대는 검사

규칙의 기준 구현은 S1 TypeScript다. 계약을 만드는 셈(`buildDeparture`)과 영수증 반영은 TS에 먼저 두고, 같은 씨앗 표본(`s1/tools/field_port_fixtures.ts` → `s2/tests/game/fixtures/field_port/field_vectors.json`)으로 GDScript가 같은 값을 내는지 본다. 열차 턴 표본(`train_vectors.json`)도 S1이 바뀔 때마다 다시 뽑는다.

| 검사 | 묻는 것 |
|---|---|
| 계약 같음 | 같은 판 상태에서 TS와 GDScript가 같은 출발 계약을 내는가 |
| 상처 그대로 | 왼팔 골절(부목)이 같은 사람·같은 부위·같은 등급으로 남고 난수가 한 걸음도 안 움직였는가 |
| 판 상태 잇기 | 다른 영수증 셋이 다른 회기 후보·표·둘째 역을 내는가, 표본 파일을 읽지 않는가 |
| 명단 그대로 | 계약의 id가 영수증 사람 목록·목격·상처에 그대로 나오는가 |
| 중단 반복 | 같은 정차를 n초마다 끊고 이은 판과 안 끊은 판의 끝 상태가 같은가 |
