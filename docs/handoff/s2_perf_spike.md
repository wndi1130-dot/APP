# 지시서: S2 첫 일 — Godot 4 폰 성능 시험

작성: 2026-10-07 · 맡길 곳: Codex 워커 · 근거: [../design/briefs/engine.md](../design/briefs/engine.md), decisions.md '개발 순서'의 엔진 항목

## 목적

Godot 4로 이 게임의 필드와 정차 장면이 사용자 폰에서 버티는지 일찍 확인한다. 안 버티면 Unity 6으로 바꾼다. 그림은 전부 회색 상자다. 예쁘게 만들지 않는다.

## 만들 것

저장소 `s2/`에 Godot 4 프로젝트(GDScript, Mobile 렌더러, 가로 화면 고정)를 만든다. 장면 셋을 한 흐름으로 잇는다.

1. **단면 홈:** 가로로 달리는 열차 단면(객차 6칸 상자), 배경이 옆으로 흐른다. 화면 아래 '정차' 버튼.
2. **정차 장면:** 버튼을 누르면 감속하며 멈추고(소리 자리만 둔다), 짧은 로딩 뒤 카메라가 옆면에서 약간 앞쪽으로 돌며 역 주변(건물 상자 몇 개, 안개)을 보여 준다. 사람 상자 하나가 내린다. 하차 자세는 두 가지를 조합 방식으로 보여 준다: 기본 하차 동작 위에 '당당함(고개 듦)'과 '처짐(어깨 처짐, 한숨 자리)' 자세 층을 섞는다. 디버그 단추로 둘을 바꾼다. 동작은 무료 마네킹 리그나 절차 애니메이션이면 된다.
3. **탑뷰 필드:** 카메라가 좀보이드식 사선 탑뷰로 넘어간다. 회색 역 하나(건물 상자, 벽, 문), 탭 이동, 좀비 100마리.
   - 좀비는 MultiMesh와 동작을 텍스처에 구운 방식(VAT)으로 그린다. 상태는 배회·추적 둘이면 된다.
   - 시야 가리기: 플레이어가 못 보는 곳(벽 뒤)을 어둡게 가린다. 격자 기반으로 계산한다.
   - 소음: 탭 한 번으로 소음을 내면 반경 안 좀비가 그쪽으로 모인다.
   - 안개와 약한 비 입자를 켠다.

## 측정

- 화면 구석에 FPS, 프레임 시간, 그려진 좀비 수를 띄운다.
- 단계별로 켜고 끌 수 있게 한다: 좀비 50/100/150, 시야 가리기, 안개, 비.
- 기준: 사용자 폰에서 좀비 100마리 + 시야 가리기 + 안개로 30fps 이상, 정차 카메라 전환 중 눈에 띄는 끊김 없음.

## 빌드와 테스트

- 헤드리스로 도는 테스트를 둔다(시야 격자 계산, 소음 반경, 장면 전환 순서). GUT나 gdUnit4 중 하나.
- GitHub Actions에서 안드로이드 APK(디버그 서명)를 만들어 실행 결과물로 올린다. 사용자가 그 APK를 폰에 깔아 본다.
- 코드는 브랜치와 PR로 올린다. 테스트와 빌드가 통과해야 합친다.

## 하지 말 것

- 저작권 있는 에셋, 남의 게임 화면, 비밀 키를 올리지 않는다(공개 저장소).
- s1/ 코드를 옮기지 않는다. 정치는 S3 전까지 웹에 있다.
- 그림을 다듬지 않는다. 회색 상자로 성능만 본다.

## 끝나면 낼 것

APK 링크, 단계별 FPS를 적을 점검표(사용자가 폰에서 채움), 스크린샷 두세 장, 막힌 것.
