## B1. 이름 풀과 한글 표기

```text
[B1] 이름 풀과 한글 표기

규칙
- 저장소 https://github.com/wndi1130-dot/APP 에서 작업한다. 먼저 docs/handoff/codex_tasks.md의 '공통 규칙'과 [B1] 항목, docs/prototype/s1_content_guide.md 2장의 '이름'을 읽는다.
- docs/는 읽기만 한다. 새 파일은 ref/names/에만 만든다.
- main에서 새 브랜치를 만들어 작업하고 PR로 낸다. main에 직접 push하지 않는다.
- 사람이 읽는 글은 한국어, 코드와 커밋 메시지는 영어로 쓴다.
- 사실엔 출처 URL을 단다. 확인 못 한 것은 '미확인'으로 적는다. 지어내지 않는다.
- 테스트는 실제로 돌려서 결과를 PR에 적는다. 돌릴 수 없는 환경이면 그렇게 적는다.
- PR 설명에 만든 것, 확인하는 명령어와 결과, 남은 문제와 미확인 목록을 적는다.

할 일
1. ref/names/pl.json, de.json, cz.json, other.json
   - pl, de, cz는 언어마다 이름 150개 이상(남녀 반반쯤), 성 200개 이상. 흔한 이름 위주로 고르고, 각국 통계청 같은 공식 통계를 출처로 단다.
   - 폴란드어·체코어 성은 남녀 형태를 모두 넣는다(예: Kowalski/Kowalska, Novák/Nováková).
   - other는 피난민용이다. 우크라이나, 슬로바키아, 헝가리, 리투아니아에서 언어마다 이름 30개, 성 40개 안팎.
   - 같은 언어 안에서 원어 표기가 겹치지 않는다.
2. 형식은 아래를 그대로 따른다. 프로필 생성기(브랜치 codex/a3-profile-generator의 s1/tools/gen_profiles.ts)가 이 키 이름으로 읽는다. 키 이름은 바꾸지 않는다. 출처나 표기 근거 같은 키는 더해도 된다. 헷갈리면 같은 브랜치의 s1/tools/README_profiles.md 'B1·B6 입력'을 본다.
   {
     "language": "pl",
     "given_names": [
       { "original": "Anna", "korean": "안나", "gender": "female", "korean_basis": "용례" }
     ],
     "surnames": [
       { "male": { "original": "Kowalski", "korean": "코발스키" },
         "female": { "original": "Kowalska", "korean": "코발스카" } },
       { "original": "Nowak", "korean": "노바크" }
     ]
   }
   - 남녀 형태가 같은 성은 두 번째 줄처럼 써도 된다.
   - korean에는 반드시 한글이 들어간다. gender는 male 또는 female.
   - korean_basis는 '용례'(국립국어원 용례가 있음), '규칙'(변환기로 만듦), '미확인' 중 하나.
3. ref/names/famous_blocklist.json: 위 나라들의 유명 실존 인물 이름+성 조합 수백 개. 정치인, 운동선수, 연예인, 역사 인물처럼 이름만 들어도 떠오르는 사람. 형식:
   { "names": [ { "original": "전체 원어 이름", "korean": "전체 한글 이름", "country": "pl", "source": "URL" } ] }
   - 생성기가 원어와 한글을 모두 대조하므로 모든 항목에 한글 전체 이름을 넣는다.
4. ref/names/transliterate.py(파이썬 표준 라이브러리만)와 test_transliterate.py: 국립국어원 외래어 표기법의 폴란드어·독일어·체코어 표기 세칙을 따르는 변환기와 테스트.
   - 테스트 사례는 국립국어원 용례에서 언어마다 20개 이상 가져오고 출처를 단다.
   - 확인용 예: Leipzig → 라이프치히, Krejčí → 크레이치, Mazurek → 마주레크. 규칙으로 맞는지 확인한다. 용례와 규칙이 다르면 데이터는 용례를 따른다.
   - 헝가리어 표기 세칙이 있으면 따른다(확인할 것). 표기 세칙이 없는 언어(우크라이나어, 리투아니아어 등)는 용례가 있는 것만 '용례'로 쓰고 나머지는 '미확인'으로 둔다.
5. ref/names/README.md: 이름 통계의 출처, 고른 방법, 표기 방법, 미확인 목록, 확인하는 명령어.

완료 기준: python3 -m unittest discover -s ref/names 가 통과한다. 네 파일이 위 형식을 따르고 모든 항목에 한글 표기가 있다. famous_blocklist의 모든 항목에 원어와 한글이 있다.
```

## B3. 증기기관차 운용

```text
[B3] 증기기관차 운용 레퍼런스

규칙
- 저장소 https://github.com/wndi1130-dot/APP 에서 작업한다. 먼저 docs/handoff/codex_tasks.md의 '공통 규칙'과 [B3] 항목, docs/design/decisions.md를 읽는다.
- docs/는 읽기만 한다. 새 파일은 ref/steam_operations.md 하나다.
- main에서 새 브랜치를 만들어 작업하고 PR로 낸다. main에 직접 push하지 않는다.
- 문서는 한국어로 쓴다. 숫자마다 출처 URL을 단다. 확인 못 한 숫자는 '미확인'으로 적는다. 문장을 베끼지 않는다.
- PR 설명에 만든 것과 미확인 목록을 적는다.

우리 게임에서 알아 둘 것
- 열차는 폴란드 볼슈틴(Wolsztyn) 증기 차고에서 출발한 증기 열차다. 붕괴 후 여섯 번째 겨울이고, 긴 겨울 사이에 짧은 해빙기가 온다.
- 석탄이 생존 자원이다. 정차 중에도 석탄이 탄다. 보일러 물은 석탄 자원에 합쳐서 다룬다.
- 앞에 불바나 쐐기형 제설기를 달아 선로 위의 눈과 무리를 밀고 간다. 쐐기형 제설기는 연구 2단계다.
- 증기 공기총은 열차의 공기 제동 압축기로 탱크를 채워 쏘는 조용한 총이다(연구 3단계).
- 기관 지식은 견습·숙련·장인 3단계다. 기관사가 모두 죽어도 기관 매뉴얼이 있으면 매우 느리게 굴러간다.

할 일: ref/steam_operations.md
1. 기관사와 화부의 일과 분업. 출발 전 점검부터 운행 뒤 정비까지.
2. 불을 넣고 출발할 수 있을 때까지 걸리는 시간, 석탄과 물 소비(형식별 대략값, 정차 중 불 유지 포함), 급수·급탄 간격, 보일러 압력과 안전밸브.
3. 볼슈틴 차고에서 지금 쓰거나 보존 중인 형식(예: Ol49, Pt47. 확인할 것)의 제원 표: 축 배치, 보일러 압력, 출력, 최고 속도, 석탄·물 적재량, 무게.
4. 겨울 운용: 인젝터 결빙, 급수탑 결빙, 눈 막힘, 혹한기 대처(불 유지, 배수, 예열).
5. 공기 제동과 증기로 돌리는 공기 압축기의 원리와 압력, 배장기와 쐐기형 제설기, 흔한 고장과 수리(현장에서 고칠 수 있는 것과 차고가 필요한 것).
6. 끝에 '게임과 닿는 곳'을 적는다. 결정은 하지 않는다.
   - 석탄 경제: 달릴 때와 정차 중의 소모 비율, 속도와 소모의 관계.
   - 제설: 눈 깊이와 제설기 종류, 기관차가 받는 부담.
   - 공기총 충전: 압축기로 탱크를 채우는 데 걸리는 시간과 기관 부담(대략).
   - 기관 지식: 견습·숙련·장인이 각각 할 수 있는 일, 매뉴얼로 배울 수 있는 일과 없는 일, 기관사 없이 매뉴얼로 몰 때 무엇이 느려지고 위험한지.
```

## A2. 핵심 로직

```text
[A2] 핵심 로직: 시드 난수, 의회 계산, 효과·조건 해석

규칙
- 저장소 https://github.com/wndi1130-dot/APP 에서 작업한다. 먼저 docs/handoff/codex_tasks.md의 '공통 규칙'과 [A2] 항목, docs/prototype/s1_political_prototype.md 4·7·8·13장, docs/prototype/s1_content_guide.md 1.9를 읽는다.
- 전제: A1(S1 뼈대와 검사기)이 main에 합쳐져 있어야 한다. s1/package.json과 s1/schema/가 없으면 시작하지 말고 그렇게 알린다. s1/ 뼈대를 새로 만들지 않는다.
- docs/는 읽기만 한다. 새 파일은 s1/src/core/와 s1/tests/core/에만 만든다. package.json, tsconfig.json, s1/schema/, s1/tools/는 고치지 않는다(다른 작업과 겹친다). 꼭 필요하면 PR에 이유를 적는다.
- main에서 새 브랜치를 만들어 작업하고 PR로 낸다. main에 직접 push하지 않는다.
- 사람이 읽는 글은 한국어, 코드와 커밋 메시지는 영어로 쓴다.
- 테스트는 실제로 돌려서 결과를 PR에 적는다. 돌릴 수 없는 환경이면 그렇게 적는다.
- PR 설명에 만든 것, 확인하는 명령어와 결과, 남은 문제를 적는다.

할 일 (s1/src/core/, 순수 함수와 타입. 화면과 파일 입출력 없음)
1. rng.ts: 시드 고정 난수(문자열 시드 허용). 같은 시드면 같은 수열. 상태를 저장했다가 이어 쓸 수 있게 한다.
2. state.ts: 게임 상태 타입과 처음 상태를 만드는 함수.
   - 공동체 5개(tail, engine, guard, medtech, front)마다 처지 수치 warmth, ration, crowding, exposure.
   - trust(신임), tension(긴장), fear(공포).
   - 자원 coal, food, medicine, luxury, 그리고 가진 상징물 id와 비밀 id 목록.
   - 사람의 상태 alive, injured, dead, away(남은 구간 수와 함께).
   - 집단 관계(relation)와 결속도(cohesion), 플래그, 예약된 후속 사건(id와 남은 구간), 진행 중인 거래와 약속(기한 구간), 일대기 기록 id.
   - 수치의 범위와 처음 값은 문서에 정해져 있지 않다. 상수 파일 하나에 임시값(예: 0~100)으로 모으고 PR에 적는다.
3. council.ts
   - 100석을 집단 인구 비례로 나눈다(최대 잔여법). 아이도 인구로 센다. 세력원은 세력 의석으로 센다(입력으로 받은 집단 목록을 그대로 쓴다). 잔여가 같으면 인구가 큰 쪽, 그다음 id 순으로 정한다.
   - 집단의 실제 표 = 의석 × (열차에 남은 인원 ÷ 전체 인원), 내림. 파견 중인 사람은 빠진다. 비율과 반올림 방식은 상수로 빼서 바꿀 수 있게 한다.
   - 결속도(0~1): 지도자가 약속한 표 중 실제로 따라오는 비율. 시드 난수로 재현된다.
   - 통과 기준: 일반 법 51표, 통치 법 67표.
```
