# S2 술레후프 필드 회색 상자

첫 정차지 술레후프(얼어붙은 급수탑)에서 열차를 내려 파밍하고 돌아오는 한 판을 회색 상자로 만든 것이다. 설계는 `docs/design/briefs/s2_station.md`(S2-1~S2-7)와 `field_unified.md`, `body_injury.md`, `weapons.md`, `zombies.md`, `survival_detail.md`, `places.md`를 따른다. 관문 질문은 **"한 번의 파밍이 짧고 긴장되는가"** 다. Godot 4.7.2 stable / GDScript / Mobile 렌더러 / 가로 화면.

## 받는 법

PR 또는 `main` push 때 GitHub Actions의 **S2 Android field graybox** 가 돈다. 실행 결과의 `s2-android-debug-<실행번호>`를 내려받아 `s2-field-debug.apk`를 폰에 깐다. 빌드마다 디버그 키가 바뀌므로 이전 앱을 지우고 깐다. 스토어용이 아니다.

## 한 판의 흐름

1. **시작 화면**: 약탈자(있음/없음), 시계(보통/2배), 파이프 산탄총 품질, 날씨, 동시 상한(60 기본), FPS 상한을 고르고 **내린다**.
2. **승강장**: 열차장과 동료 셋이 내린다. 10:30 도착, 해 질 녘 15:45. 실제 1분이 게임 15분이다. 20분(1,200초)까지가 안전, 30분이 끝이다.
3. **파밍**: 역사(대합실·매표소·역무실·매점·화장실), 급수탑, 석탄 측선, D 거리(약국 등), 사다리 위 신호소. 방은 한 번 본 뒤에야 이름이 뜬다.
4. **석탄 작업**: 측선 둘레 16m 안에 서 있는 것이 없으면 작업조 넷과 호위 둘을 부른다. 캐면 1분마다 곡괭이 소리가 난다.
5. **출발**: 승강장에서 **출발** 을 누르면 기적을 울리고 떠난다. 승강장에 없는 사람은 남는다. 끝 화면에 정차 영수증(JSON)과 기록이 나온다.

## 무엇이 들어 있나

- **시야**: 앞 160도 원뿔(맑은 낮 18칸) + 등 뒤 2칸, 벽 뒤는 가린다. 본 곳은 어둡게 기억한다. 안개 ×0.6, 밤 ×0.55, 눈 ×0.85이고 겹치면 짧은 쪽 하나만 쓴다. 사람과 좀비 모두 같은 배율을 받는다.
- **소리**: 조용·보통·큼·아주 큼 네 단계(3/12/35m/지도 전체), 실내는 절반, 바람 아래쪽으로 더 멀리. 하수구 입구 4m 안 소리는 한 단계 커지고, 큰 소리가 열린 하수구 12m 안이면 그 하수구에서 무리가 올라온다. 총은 탄피를 남기고 실내 사격은 5초 귀가 먹먹하다.
- **피 냄새**: 심한 출혈이나 피범벅(가까이서 셋을 연달아 죽임)이면 1분마다 12m 냄새 사건을 낸다. 바람 아래 ×1.5, 위 ×0.6, 옆 ×0.9, 영하 ×0.6. 좀비는 그 자리로 오고 사람의 지금 위치는 모른다. 눈으로 문질러 지우면 체온이 떨어진다.
- **무리**: 동시 상한 60(화면 + 열차 둘레). 뒤로 오는 무리는 끝이 없다. 입구 다섯 곳(급수탑 밑 암거, 거리 맨홀, 동쪽 선로 끝, 북쪽 길, 남쪽 길). 하수구는 오기 3초 전에 덜컹거리고, 사람이 6m 안에 있으면 다른 하수구로 나온다. 암거는 한 번에 둘이 나온다. 맨홀은 판자·고철·나무로 막을 수 있고 암거는 못 막는다. 기관사가 무전으로 미리 알려 준다.
- **좀비 상태**: 배회 → 소리 쪽으로 몸을 돌린 뒤 감 → 쫓음 → 놓치면 마지막으로 본 자리까지 가서 4초 둘러보고 배회로. 본 자리만 기억하고(8초) 지금 위치를 다시 읽지 않아서 모퉁이를 돌아 따돌릴 수 있다. 약한 소리는 더 큰 소리를 쫓는 좀비를 돌리지 못한다. 얼어붙은 자, 새로 일어나는 시체, 쓰러졌다 일어나는 것.
- **몸**: 출혈·물림·골절·추위(이 판은 '추움' 켜짐/꺼짐만, 초상 테두리 성에)·지침. 붕대·부목·직접 치료.
- **약탈자**: 약국에 숨어 있다. 쏘는 자·다가오는 자·옆으로 도는 자로 나뉘고, 사기가 꺾이면 달아나거나 항복한다(데려가기·무장 해제·쏘기 카드).
- **카드**: 선택지는 열차장이 외치는 말과 그 밑의 비용 줄(S1a 방식).

## 시험

GUT 192개(계산 모듈, 무리 감독, 날씨, 지도·길·시야, 좀비 감각과 하수구). 자동 판(시드 7)은 30분 판을 끝까지 돌고 영수증 검사를 통과한다. PC에서 한 걸음 계산은 약 2ms(좀비 0.7ms, 시야는 0.1초마다 0.6ms)다. 폰 숫자는 아직 없다.

## 이전 판: 성능 시험

갤럭시 S22에서 필드와 정차 카메라가 버티는지 재는 회색 상자다. **Godot 4.7.2 stable / GDScript / Mobile 렌더러 / 가로 화면**을 사용한다. 4.8 개발판이나 다른 렌더러로 바꾸면 같은 시험으로 비교하지 않는다. `s1/` 코드와 외부 에셋을 쓰지 않는다.

GUT 테스트와 APK 내보내기는 GitHub Actions에서 돈다. S22 측정은 아직 하지 않았다.

### 실행

Godot 4.7.2가 이미 설치된 환경에서 `s2/project.godot`를 열고 F6 대신 프로젝트 실행(F5)을 누른다. 명령줄에서는 설치한 실행 파일의 **절대경로**로 다음과 같이 실행한다.

```powershell
& 'C:\설치경로\Godot_v4.7.2-stable_win64.exe' --path 'C:\저장소\s2'
```

예시 경로는 실제 설치 경로로 바꾼다. 여기서 엔진을 설치하거나 내려받지는 않았다. 실행 시 VAT를 한 번 생성하고 홈을 연다. 프레임 측정은 화면의 FPS와 Frame 값을 본다.

(이 판의 APK도 지금은 아래 필드판 APK 안에 들어 있다. 시작 화면의 **성능 시험 (이전 판)** 으로 연다.) 예전에는 GitHub Actions 실행 결과의 `s2-perf-debug.apk`를 S22에 복사해 설치한다. 디버그 서명 키를 CI가 빌드마다 새로 만들기 때문에, 새 APK를 다시 깔 때는 먼저 이전 앱을 지우고 깔아야 한다. 디버그 APK는 배포·스토어 제출용이 아니다. 실패한 CI의 artifact는 로그만 있을 수 있으므로 작업 성공과 APK 존재를 확인한다.

CI는 엔진과 템플릿을 공식 `godotengine/godot-builds`의 `4.7.2-stable` 릴리스에서 받고 SHA-512 목록과 대조한다. Linux 일반 실행 파일을 `--headless`로 실행한다. 템플릿 폴더는 `4.7.2.stable`이다. GUT `9.7.1`은 `bitwes/Gut`의 고정 태그에서 CI 작업에만 받아 라이선스를 함께 둔다. 저장소에는 프레임워크·키스토어·APK를 넣지 않는다. CI는 Java 17, Android SDK 35 / build-tools 35.0.0을 사용한다. 이 조합과 릴리스 파일의 현재 가용성은 아직 실호출로 확인하지 않았다.

### 장면 흐름과 단추

1. **단면 홈**: 객차 여섯 칸, 옆으로 흐르는 배경. 아래 **정차**를 누른다.
2. **정차**: 약 2초 감속 → 0.45초 로딩 표시 → 2.4초 카메라 회전과 3.2초 하차. 하차가 끝나면 **필드 진입**을 누른다. 이 대기 구간에서 두 자세를 비교할 수 있다.
3. **탑뷰 필드**: 카메라가 1.8초 동안 사선 탑뷰로 이동한다. 바닥을 탭해 이동한다. 벽은 통과하지 않는다. 벽 너머 목적지로 바로 경로를 찾는 기능은 없으므로 문까지 중간 지점을 탭한다.

| 단추 | 동작 |
|---|---|
| 자세: 당당함 / 처짐 | 기본 하차 보행에 고개 듦 또는 어깨 처짐·가슴 호흡 층을 더한다. 홈에서도 미리 선택 가능 |
| 좀비: 100 | 누를 때마다 100 → 150 → 50 → 100. 기본값 100 |
| 정점: 1764 | 좀비 한 마리의 정점 수. 누를 때마다 1,500 → 3,000 → 144 단계로 바뀌고 실제로 구운 수(1,764 / 3,600 / 144)를 보여 준다. 기본값은 1,500 단계. 처음 고른 단계는 그 자리에서 VAT를 새로 구워 `Max(120f)`가 한 번 튈 수 있고, 다시 고를 때는 구워 둔 것을 쓴다 |
| 시야 가리기 | 반경 16칸 격자 시야. 벽 자체는 보이고 뒤는 어두운 격자 평면으로 가린다 |
| 안개 | Mobile에서 가능한 일반 깊이 안개. 정차와 필드에 적용 |
| 비 | 필드의 약한 GPU 비 입자 256개. 끄면 기존 입자가 수명(1.3초) 후 사라짐 |
| 그림자 | 필드의 해 하나(DirectionalLight3D) 그림자. 그림자 거리 65로 사선 탑뷰 화면을 덮는다. 좀비 그림자도 VAT 동작을 따라간다 |
| 소음 (반경 12m) | 플레이어 위치에서 12m 안 좀비가 6초 동안 그 위치로 추적. 벽에 의한 소리 감쇠는 없음 |
| 홈부터 다시 | 필드에서 홈으로 돌아간다. 설정은 유지하고 필드 시간은 새 진입 때 초기화 |

필드 기본값은 좀비 100, 정점 1,500 단계, 시야·안개·비·그림자 모두 ON이다. 제동·한숨 소리는 자리만 마련했고 실제 소리 파일은 없다. 임의 프레임워크 라이선스를 만들거나 외부 폰트를 다운로드하지 않는다. UI는 기기의 시스템 글꼴을 쓰므로 한글 표시 상태는 APK에서 확인해야 한다.

### 측정 방법

화면 구석에는 FPS, 최근 120프레임의 평균 Frame(ms), 같은 구간의 최대 프레임 간격, 좀비 제출 수/설정 수, 필드 진입 후 시간, 기능 ON/OFF, 마지막 소음의 반응 수가 보인다. `Frame`은 화면 프레임 간격이며 GPU 실행 시간만을 따로 잰 값은 아니다. `Max(120f)`는 정차 전환의 순간 끊김을 함께 보는 보조 수치다.

**좀비 제출 수**는 시야와 카메라 범위를 통과한 뒤 MultiMesh의 `visible_instance_count`에 넣은 수다. GPU 픽셀·깊이 가림 결과를 읽어 센 값은 아니다. 설정 100이어도 벽 뒤나 카메라 밖 좀비 때문에 제출 수는 작을 수 있다. 시야 OFF 조건과 소음으로 모인 조건도 비교하고 제출 수를 점검표에 함께 기록한다.

각 조건은 홈부터 동일한 흐름과 위치로 시작한다. 밝기·화면 주사율·충전 상태·절전 설정을 고정하고, 처음 1분 부근의 FPS/Frame과 **앱을 포그라운드에서 계속 돌린 10분 뒤**의 값을 적는다. 조건을 바꿀 때는 새 실행으로 시간을 시작한다. 정지 화면 한 번의 최고 FPS 대신 10초 동안의 범위와 대표값을 기록한다. 필요하면 시험 사이 기기를 식힌다. 캡처나 녹화 중 값은 별도로 표시한다.

필수 기준은 **좀비 100 + 정점 1,500 단계 + 시야 ON + 안개 ON + 그림자 ON**에서 10분 뒤 **30fps 이상**(33.33ms 이하), 정차 카메라의 눈에 띄는 끊김 없음이다. 처음 1분 **45fps 이상**(22.22ms 이하)은 여유 기준이다. 비 OFF/ON을 각각 비교한다. 사용자가 채울 표는 [PERF_CHECKLIST.md](PERF_CHECKLIST.md)에 있다.

이 회색 상자는 스켈레톤·텍스처 에셋·정식 내비게이션을 넣지 않았다. 결과는 이 부하의 엔진 선택 근거이며 최종 게임 전체의 성능 보증이 아니다.

### 테스트와 정적 확인

GUT은 시야 범위·벽·문·대각 모서리, 소음 반경 경계, 장면 순서·중복 전환·초기화, VAT 정점 단계와 텍스처 접기를 검사한다. 로컬에서는 `tests/.gdignore`가 GUT 없는 테스트의 자동 임포트를 막는다. CI는 GUT을 받은 뒤 임시 checkout에서 이 표시만 제거하고 테스트를 임포트한다. CI에서 다운로드한 GUT이 있고 테스트 임포트를 활성화한 환경의 명령은 다음과 같다.

```text
<Godot 4.7.2 실행 파일> --headless --path s2 --editor --quit
<Godot 4.7.2 실행 파일> --headless --path s2 --script addons/gut/gut_cmdln.gd -gdir=res://tests -ginclude_subdirs -gexit -gjunit_xml_file=res://build/gut-results.xml
```

CI는 테스트 전에 `scripts/`와 `tests/`의 모든 스크립트를 하나씩 `--check-only`로 읽어 문법 오류를 한 번에 보여 준다.

### VAT 구조

`scripts/vat_baker.gd`가 머리·몸통·팔·다리 상자 여섯 개를 잘게 나눠 고른 정점 수(144 / 1,764 / 3,600)를 만들고, 배회/추적 두 클립 × 32프레임의 변위를 RGBA8 텍스처에 절차적으로 굽는다. 텍스처 폭은 정점 수와 같고(3,600 단계는 3600×64), 정점이 4,096개를 넘으면 한 프레임을 여러 줄로 접는다. `UV2.x`는 줄 안의 텍셀 중심, `UV2.y`는 접힌 줄 번호, 셰이더의 `rows_per_frame`은 프레임당 줄 수다. 인스턴스 custom data는 위상과 클립 번호다. `shaders/zombie_vat.gdshader`가 인접 프레임을 보간한다. GPU 하나의 MultiMesh에 최대 150개를 제출하고 CPU는 30Hz로 위치·상태, 10Hz로 시야를 계산한다. VAT는 런타임에 생성하며 텍스처 파일이나 리그를 내려받지 않는다. 바뀐 정점의 법선은 원래 상자 법선으로 근사한다.
