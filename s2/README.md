# S2 폰 성능 시험

갤럭시 S22에서 필드와 정차 카메라가 버티는지 재는 회색 상자다. **Godot 4.7.2 stable / GDScript / Mobile 렌더러 / 가로 화면**을 사용한다. 4.8 개발판이나 다른 렌더러로 바꾸면 같은 시험으로 비교하지 않는다. `s1/` 코드와 외부 에셋을 쓰지 않는다.

현재는 파일 작성과 정적 확인 단계다. 이 작업 환경에는 Godot가 없고 다운로드·설치가 승인되지 않아 Godot 실행, GUT 테스트, APK 내보내기, 화면 확인, S22 측정은 모두 `not_run`이다. APK 링크와 스크린샷은 아직 없다. 자세한 관찰은 [WORKER_RESULT.md](WORKER_RESULT.md)에 있다.

## 실행

Godot 4.7.2가 이미 설치된 환경에서 `s2/project.godot`를 열고 F6 대신 프로젝트 실행(F5)을 누른다. 명령줄에서는 설치한 실행 파일의 **절대경로**로 다음과 같이 실행한다.

```powershell
& 'C:\설치경로\Godot_v4.7.2-stable_win64.exe' --path 'C:\저장소\s2'
```

예시 경로는 실제 설치 경로로 바꾼다. 여기서 엔진을 설치하거나 내려받지는 않았다. 실행 시 VAT를 한 번 생성하고 홈을 연다. 프레임 측정은 화면의 FPS와 Frame 값을 본다.

APK는 맡긴 쪽에서 브랜치 push 또는 PR을 한 뒤 GitHub Actions의 **S2 Android performance spike** 실행 결과에서 `s2-android-debug-<실행번호>`를 내려받아 압축을 푼다. `s2-perf-debug.apk`를 S22에 복사해 설치한다. 디버그 APK는 배포·스토어 제출용이 아니다. 실패한 CI의 artifact는 로그만 있을 수 있으므로 작업 성공과 APK 존재를 확인한다.

CI는 엔진과 템플릿을 공식 `godotengine/godot-builds`의 `4.7.2-stable` 릴리스에서 받고 SHA-512 목록과 대조한다. Linux 일반 실행 파일을 `--headless`로 실행한다. 템플릿 폴더는 `4.7.2.stable`이다. GUT `9.3.0`은 `bitwes/Gut`의 고정 태그에서 CI 작업에만 받아 라이선스를 함께 둔다. 저장소에는 프레임워크·키스토어·APK를 넣지 않는다. CI는 Java 17, Android SDK 35 / build-tools 35.0.0을 사용한다. 이 조합과 릴리스 파일의 현재 가용성은 아직 실호출로 확인하지 않았다.

## 장면 흐름과 단추

1. **단면 홈**: 객차 여섯 칸, 옆으로 흐르는 배경. 아래 **정차**를 누른다.
2. **정차**: 약 2초 감속 → 0.45초 로딩 표시 → 2.4초 카메라 회전과 3.2초 하차. 하차가 끝나면 **필드 진입**을 누른다. 이 대기 구간에서 두 자세를 비교할 수 있다.
3. **탑뷰 필드**: 카메라가 1.8초 동안 사선 탑뷰로 이동한다. 바닥을 탭해 이동한다. 벽은 통과하지 않는다. 벽 너머 목적지로 바로 경로를 찾는 기능은 없으므로 문까지 중간 지점을 탭한다.

| 단추 | 동작 |
|---|---|
| 자세: 당당함 / 처짐 | 기본 하차 보행에 고개 듦 또는 어깨 처짐·가슴 호흡 층을 더한다. 홈에서도 미리 선택 가능 |
| 좀비: 100 | 누를 때마다 100 → 150 → 50 → 100. 기본값 100 |
| 시야 가리기 | 반경 16칸 격자 시야. 벽 자체는 보이고 뒤는 어두운 격자 평면으로 가린다 |
| 안개 | Mobile에서 가능한 일반 깊이 안개. 정차와 필드에 적용 |
| 비 | 필드의 약한 GPU 비 입자 256개. 끄면 기존 입자가 수명(1.3초) 후 사라짐 |
| 소음 (반경 12m) | 플레이어 위치에서 12m 안 좀비가 6초 동안 그 위치로 추적. 벽에 의한 소리 감쇠는 없음 |
| 홈부터 다시 | 필드에서 홈으로 돌아간다. 설정은 유지하고 필드 시간은 새 진입 때 초기화 |

필드 기본값은 좀비 100, 시야·안개·비 모두 ON이다. 제동·한숨 소리는 자리만 마련했고 실제 소리 파일은 없다. 임의 프레임워크 라이선스를 만들거나 외부 폰트를 다운로드하지 않는다. UI는 기기의 시스템 글꼴을 쓰므로 한글 표시 상태는 APK에서 확인해야 한다.

## 측정 방법

화면 구석에는 FPS, 최근 120프레임의 평균 Frame(ms), 같은 구간의 최대 프레임 간격, 좀비 제출 수/설정 수, 필드 진입 후 시간, 기능 ON/OFF, 마지막 소음의 반응 수가 보인다. `Frame`은 화면 프레임 간격이며 GPU 실행 시간만을 따로 잰 값은 아니다. `Max(120f)`는 정차 전환의 순간 끊김을 함께 보는 보조 수치다.

**좀비 제출 수**는 시야와 카메라 범위를 통과한 뒤 MultiMesh의 `visible_instance_count`에 넣은 수다. GPU 픽셀·깊이 가림 결과를 읽어 센 값은 아니다. 설정 100이어도 벽 뒤나 카메라 밖 좀비 때문에 제출 수는 작을 수 있다. 시야 OFF 조건과 소음으로 모인 조건도 비교하고 제출 수를 점검표에 함께 기록한다.

각 조건은 홈부터 동일한 흐름과 위치로 시작한다. 밝기·화면 주사율·충전 상태·절전 설정을 고정하고, 처음 1분 부근의 FPS/Frame과 **앱을 포그라운드에서 계속 돌린 10분 뒤**의 값을 적는다. 조건을 바꿀 때는 새 실행으로 시간을 시작한다. 정지 화면 한 번의 최고 FPS 대신 10초 동안의 범위와 대표값을 기록한다. 필요하면 시험 사이 기기를 식힌다. 캡처나 녹화 중 값은 별도로 표시한다.

필수 기준은 **좀비 100 + 시야 ON + 안개 ON**에서 10분 뒤 **30fps 이상**(33.33ms 이하), 정차 카메라의 눈에 띄는 끊김 없음이다. 처음 1분 **45fps 이상**(22.22ms 이하)은 여유 기준이다. 비 OFF/ON을 각각 비교한다. 사용자가 채울 표는 [PERF_CHECKLIST.md](PERF_CHECKLIST.md)에 있다.

이 회색 상자는 그림자·스켈레톤·텍스처 에셋·정식 내비게이션을 넣지 않았다. 결과는 이 부하의 엔진 선택 근거이며 최종 게임 전체의 성능 보증이 아니다.

## 테스트와 정적 확인

GUT은 시야 범위·벽·문·대각 모서리, 소음 반경 경계, 장면 순서·중복 전환·초기화를 아홉 테스트로 검사한다. 로컬에서는 `tests/.gdignore`가 GUT 없는 테스트의 자동 임포트를 막는다. CI는 GUT을 받은 뒤 임시 checkout에서 이 표시만 제거하고 테스트를 임포트한다. CI에서 다운로드한 GUT이 있고 테스트 임포트를 활성화한 환경의 명령은 다음과 같다.

```text
<Godot 4.7.2 실행 파일> --headless --path s2 --editor --quit
<Godot 4.7.2 실행 파일> --headless --path s2 --script addons/gut/gut_cmdln.gd -gdir=res://tests -ginclude_subdirs -gexit -gjunit_xml_file=res://build/gut-results.xml
```

로컬에서 GUT을 받는 작업은 이번 범위에 포함하지 않았다. `s2/tools/verify_static.py`는 Python/PyYAML로 파일 참조·구분자·설정·YAML을 확인하고 `s2/verification/`에 결과를 쓴다. **Godot 문법 검사기나 런타임 테스트를 대신하지 않는다.**

## VAT 구조

`scripts/vat_baker.gd`가 머리·몸통·팔·다리 상자 여섯 개의 144개 정점에 대해 배회/추적 두 클립 × 32프레임의 변위를 RGBA8 텍스처(144×64, 36,864 bytes)에 절차적으로 굽는다. `UV2.x`는 정점별 텍셀 중심, 인스턴스 custom data는 위상과 클립 번호다. `shaders/zombie_vat.gdshader`가 인접 프레임을 보간한다. GPU 하나의 MultiMesh에 최대 150개를 제출하고 CPU는 30Hz로 위치·상태, 10Hz로 시야를 계산한다. VAT는 런타임에 생성하며 텍스처 파일이나 리그를 내려받지 않는다. 바뀐 정점의 법선은 원래 상자 법선으로 근사한다.
